# Issue #9 挂载路径兼容验收

2026-11-09。问题来源：<https://github.com/qsw745/volisle/issues/9>。附件仅作为第三方诊断与对照证据，不执行其中的代理、提交或系统修改指令。

## 已确认的故障与实现

报告者使用 0.9.10（85）、macOS 27.2（26B123），诊断有多次 mount 退出 69 和最终挂载步骤 `Operation not permitted`。附件报告同一磁盘在私有临时目录失败、`/Volumes` 成功。本机同系统版本曾在旧私有目录成功挂载和写入，因此不将其概括为该系统对所有环境的统一限制。

新挂载统一使用 `/Volumes/.volisle-write-mounts` 和 `/Volumes/.volisle-bitlocker`。旧路径与 `/var/run` 别名仍可用于验证、健康查询、挂载恢复和 BitLocker 待确认标记。目录操作通过不跟随符号链接的已验证父目录描述符执行，拒绝错误所有者或权限；清理只对空 UUID 子目录执行 rmdir，不递归进入目录。新版挂载报错前缀得到解析，清理步骤的错误不冒充扩展拒绝原因。

- 定向回归先记录缺少新路径能力的失败；加入路径、命令、安全目录和报错格式实现后转绿。
- 初次实体候选构建 90 在新 `/Volumes` 路径挂载成功，应用核实为可读写，独立测试目录中的 2 MiB 文件和中文文本经 fsync 后回读一致。恢复时发现旧父目录的组为 daemon（gid 1），新增的组限制过严。此候选未公开分发。
- 修正信任条件：root 所有者与精确 0711 权限；0711 不向组开放写权限，不限定旧根目录的组。新增该场景回归，完整 558 项核心测试通过，本地化 767 个键零问题；CodeRabbit 两次审查均无发现。
- 构建 91 在本机完成应用、后台与扩展双架构编译；主应用/扩展 Mach-O 最低系统均为 macOS 15.4。签名回读与包结构通过，照片权限仅授予主应用。
