# 原始设备只读句柄与后台连接验收

日期：2026-09-25。

## 实现

新增 `RecoveryReadOnlyDevice`，在已经取得原生占用的恢复工作线程内打开 `/dev/rdisk…` 字符设备，始终使用 `O_RDONLY | O_NOFOLLOW | O_CLOEXEC`。设备对象不公开文件描述符，也没有写入方法；作用域正常结束、校验失败、操作抛错或取消退出时关闭句柄，再由外层释放磁盘占用。

传输目标只能在 `NativeRecoveryDiskClaim.swift` 内由当前占用对象构造。正式入口 `withPhysicalReadOnlyDevice` 继续应用外接 USB 分区、当前启动标识、媒体注册身份、整盘/分区占用及未挂载检查。调试入口仅允许原有严格限定的新建只读测试镜像。

每次读取前后都会核对：工作线程及取消状态、原生占用、句柄与路径的设备类型/设备号/inode、只读及 close-on-exec 标记、从已持有句柄查询的逻辑扇区大小和容量、NTFS 引导标识和预期启动扇区 SHA-256。读取必须按逻辑扇区对齐，单次最多 1 MiB，不能越界，短读或系统错误直接失败。失败会使整个后台工作失效，即使调用方捕获读取错误，也无法转成恢复成功。

新增很小的 `VolisleDiskIO` C 模块，通过本机 SDK 定义的 `DKIOCGETBLOCKSIZE`、`DKIOCGETBLOCKCOUNT` 查询句柄。没有手写 ioctl 数值，也没有写入、缓存同步、修复或卸载指令。Swift 侧对零容量、异常扇区大小和乘法溢出再做检查。本机 SDK `sys/disk.h` 是构建依据；Apple 的 [FSKit blockSize 文档](https://developer.apple.com/documentation/fskit/fsblockdeviceresource/blocksize) 说明了逻辑扇区大小与该设备查询的对应关系。

## 验证

新增 5 个核心测试入口（参数化共 11 个场景，另含范围边界子检查）：异常扇区大小、容量为零或溢出、对齐及范围限制、无效/非磁盘句柄不能提供设备容量、非法摘要拒绝进入物理设备操作。

真实镜像测试通过 `/dev/rdisk…` 读取头部 1 MiB 和末尾 512 字节，与独立读取的镜像文件内容逐字节对照一致；同时核验零长度尾部读取、错误启动摘要、非法读取后的持续拒绝、操作异常和取消后的再次占用。没有退回读取普通镜像文件来冒充原始设备结果；普通文件只作为独立预期值。

测试只在自己的进程枚举 `/dev/fd` 并按字符设备号匹配，确认作用域内确实增加一个设备句柄；正常完成、错误和取消退出后，匹配句柄集合恢复原值。没有为了验证而向产品对象添加描述符访问接口。取消期间，工作尚未退出时，独立会话的占用请求仍被拒绝。

## 边界与下一步

这是生产代码中的只读原始设备传输层，尚未接入后台 XPC 的恢复操作；正式物理 USB 入口没有在 qsw 上执行。镜像原始设备读取通过，不代表真实 USB 热拔插、睡眠、重连、设备号复用或多分区已经验收。

本轮没有打开可写原始设备，也没有实现新的恢复写入入口。下一步仍需：日志认证与恢复授权、生产卷身份/检查点、可写句柄的同等绑定及恢复读写、后台恢复协议和 FSKit 持续日志接入。Disk Arbitration 协调不等于内核对所有特权程序的独占；校验与 I/O 之间仍有窗口，阻塞系统调用也尚无强制中断能力。

构建产物未安装、签名公证或发布；未操作 2 TB qsw、修改权限、部署官网或更新源。原有 6 项发布阻断保持，不能据此宣布完整产品可正式发布。
