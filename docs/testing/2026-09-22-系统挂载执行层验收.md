# 系统挂载执行层：真实只读镜像验收

## 结果

新增 Swift 系统挂载执行层已经通过新建 64 MiB NTFS 镜像的真实系统验收：绑定实际设备、调用盘屿 FSKit 扩展只读挂载、核对系统挂载来源和标志、读取中文文件并比对 SHA-256、验证创建文件返回 EROFS、正常卸载并移除空挂载目录。测试工具随后正常分离镜像，整份镜像摘要与准备记录一致。

这次调用真实系统工具和已安装扩展，不是模拟挂载结果。但它仍是**只读执行层验收**，不是主应用写入功能、常驻管理员服务或正式即插即用验收。

最终证据：`.workbench/fskit-readonly-j3sf38vn/system-transport-result.json`，所有成功字段为 true；汇总与日志在 `.workbench/system-mount-20260922/`。

## 接入方式与边界

`SystemFSKitMount.swift` 提供 `ReadOnlyDeviceBinding` 和 `FSKitReadOnlyMountSession`：

- 绑定当前 BSD 名称、IOMedia 注册标识、容量和独立提供的 NTFS 引导区 SHA-256；持有 O_RDONLY、O_NOFOLLOW、O_CLOEXEC 打开的块设备描述符，检查块设备类型和设备号，在挂载前后重验身份与引导摘要。
- 拒绝内部磁盘。虚拟接口没有“外置”字段时，只允许经 hdiutil 确认为当前用户拥有的普通只读镜像，且镜像与唯一设备、容量一致。未知虚拟设备不能因此放行。
- 扩展必须唯一启用，且注册位置与指定安装副本一致。
- 只创建自己的内部临时挂载目录；固定调用 `/sbin/mount -F -k -t volisle -o rdonly,nosuid,nodev`，通过参数数组执行，不使用 shell，也不接受任意命令、挂载路径、写入或强制选项。
- 独立读取系统挂载表，核对原设备、精确挂载点、文件系统类型与 readonly/nosuid/nodev 标志。
- 只对自己核验过的设备与路径执行正常 `/sbin/umount`。等待子进程结束，不因 UI 取消而杀进程或提前返回。只用 rmdir 删除空目录，不递归删除挂载路径。

Apple 说明 FSKit 与系统现有工具集成，包括 mount；参见 [FSKit 官方文档](https://developer.apple.com/documentation/fskit)。本机 mount(8) 手册说明 `-F` 选择 FSKit，`-k` 要求挂载系统调用不跟随挂载目录中的符号链接。这条已验证的工具路径与此前缺少客户端块资源构造入口的 FSClient 直接调用路径不同。

## 本机发现的两项接入条件

第一轮被外置设备检查拒绝。随后只读查看 Disk Arbitration 描述，确认该镜像的 `DADeviceInternal` 缺失、协议为 `Virtual Interface`。增加独立的镜像归属校验路径后通过；没有把缺失字段默认当作外置盘。该次失败后的镜像正常分离，摘要未变。

第二轮被扩展就绪检查拒绝。对比查询程序发现：本机未签名程序返回空的匹配列表，使用现有 Developer ID 证书签名后的同一程序能够查到唯一启用的盘屿扩展。只签名了本地诊断/验收程序，没有更改描述文件、系统权限或已安装应用。

第三轮完成真实只读闭环。随后加入实际设备绑定错误的负向验证，最终一轮再次通过：错误引导摘要和错误 IOMedia 标识均在进入挂载前被拒绝。

## 验证与运行

- 核心测试 **77 项、9 个测试组全部通过**，包含设备名注入/无效格式、缺失身份、未知虚拟设备以及错误挂载来源/类型/路径/标志的拒绝检查。
- 新增开发验收程序 `apps/macos/Sources/VolisleMountProbe/main.swift`；它只接受单个已连接的 64 MiB 普通测试镜像，独立核对 hdiutil 归属，不作为主应用内的通用设备操作入口，也不嵌入应用包。
- `scripts/test-system-mount.py` 校验夹具记录、只读连接镜像、运行 Swift 验收、正常分离并核对整份摘要；拒绝重复运行已有结果的夹具。
- Python 语法检查和 `scripts/build-macos.sh` 本地客户端构建通过。
- 最终查询未见本轮残留挂载，2 TB `qsw` 仍以 read-only 挂载；已安装测试应用严格签名验证通过。本轮未访问其测试目录或写入其文件，没有 sudo 或密码提示。

复现时先用 `scripts/test-fskit-readonly.py --prepare` 生成新夹具。本地构建 VolisleMountProbe 后，使用配置中已验证的开发者身份签名该验收程序，再执行：

```sh
python3 scripts/test-system-mount.py \
  --fixture .workbench/新生成的夹具目录 \
  --probe apps/macos/.build/out/Products/Debug/VolisleMountProbe
```

构建输出目录应以本机 `swift build --package-path apps/macos --show-bin-path` 为准；重新编译后须重新核验验收程序签名。上述命令示例中的夹具目录需替换为实际新建路径。

## 后续仍需完成

这段执行层尚未接到主应用按钮，主应用仍使用 `ReadOnlyFSKitEngine`。它不提升权限、不提供 XPC 服务，也不代表真实外接盘无需管理员权限。现有 Apple 原生挂载 entitlement 的诊断仍只描述 FSClient 直接 API 路径。

常驻授权组件还需完成签名客户端验证、登录会话与可移动磁盘权限验证、服务自建可信路径和资源绑定、跨进程互斥/持久恢复及安装卸载。当前开发进程的临时目录和内存对象不能直接充当 root 服务的安全边界。

写入仍需接通只读风险预检、扩展持有资源的再次检查及写入范围策略。Windows 双向验证、物理插拔、大文件、长期压力和正式发行验收仍未完成。
