# 挂载前预检与结果复核

2026-09-21。用户授权在未连接测试硬盘时先推进可独立完成的开发；真实硬盘仍在备份流程中。本轮没有查询用户磁盘内容、挂载镜像、操作原始设备、安装扩展或公开发布。

## 已完成的实现

### 挂载结果在设备锁内复核

`MountCoordinator` 原先直接返回引擎回调的 URL。手动 UI 有额外检查，自动挂载没有同等检查，而且手动检查发生在协调器释放设备锁之后。

现在两个入口统一在协调器内重新解析当前卷，验证连接身份、保护范围、设备组、BSD 名称、风险状态、本地文件 URL、挂载路径和系统可写状态。检查完成前不释放设备锁；任务在检查期间被取消也不提前释放。缺少可写状态或返回错误路径时抛出 `VolumeError.mountNotVerified`。发现卷已变为可写或状态未知时，手动请求也拒绝接管，包含预检期间发生的变化。

此检查只能证明系统观察状态匹配，不能独立证明是盘屿提供写入，更不能代替实际引擎的句柄与安全检查。正式写入适配器仍未接入。

### 实验扩展在可写激活前只读预检

新增 `WriteMountPolicy.requiresReadOnly`：保留现有 64 MiB/指定序列号/显式写入选项限制，对符合实验范围的请求调用只读预检。仅 `NK_CHECK_CLEAN` 允许进入后续可写挂载；脏卷、无法排除的休眠风险、异常日志、未知值及读取错误均拒绝激活。只读请求保持可读，不额外执行写入资格检查。

`NTFSVolume` 使用 FSKit 已持有的资源执行 `nk_inspect`，只提供读取回调，不提供写入和刷新回调。预检发生在只读引擎打开和可写挂载返回之前。原有首次写入时的底层二次预检、失败后恢复读取、失败会话禁止继续写入仍保留。早期预检结果不作为长期可写许可，不修改 dirty 标记。

## 后续系统验收与剩余工作

`test-fskit-interruption.py` 已调整：进程中断后的脏卷应在可写挂载阶段失败；连续三次失败均须正常释放自己的镜像设备，之后只读重挂并核对内容与镜像摘要。还要求本扩展日志明确记录 dirty 预检，不能把其他挂载失败误记为通过。新版脚本仅完成语法检查，尚未实际运行；2026-09-20 的中断通过记录仍对应旧安装候选，不能移用为新版本的系统验收。
