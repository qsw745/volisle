# 可信凭据替换中断恢复验收

日期：2026-09-25。本轮增加显式的可信凭据发布中断恢复：临时快照已完整写入但尚未完成替换时，不再只能永久拒绝；在验证旧快照、新快照和对应块日志一致后，可以完成替换。26 项专项和核心 179 项测试通过，真实引擎矩阵扩展为 245 项；最终执行结果与路径以本轮交接文件为准。尚未接入正式 root 后台或 FSKit 持续挂载会话。

## 恢复条件

普通 `fixture` / `system` 打开方式保持严格行为，遇到遗留临时文件依旧拒绝。新的 `recovering` 模式必须显式使用，不初始化空目录、不补造丢失密钥或主快照。

恢复模式只接受私有目录中的密钥、原快照以及恰好一个规范命名的临时快照。两个快照都必须通过 HMAC 认证与完整结构验证。临时快照必须恰好新增一个序号为 1 的事务，或将一个已有事务的序号推进一；不能删除其他事务、改变绑定、跳号、同时更新多个事务，或重复旧状态。临时快照尚未发布期间，普通取密钥、读凭据及更新操作被禁止。

`finishInterruptedPublication` 再核对对应块日志：整个日志完整认证，最终凭据必须精确匹配临时快照；已有事务的旧凭据还必须精确匹配同一日志中的旧前缀。先刷新日志，再在持续持有日志目录锁期间重新核对旧/新凭据文件，刷新临时文件、原子替换、刷新目录，完成最终读回后才允许正常访问。

因此，“新状态认证有效”本身不够。测试发现并修复了旧前缀也必须显式比较的缺口：即使原快照和临时快照分别有有效认证，历史不一致仍会拒绝。旧快照或临时文件无效、日志缺失或被占用时均保留原状态，不挑选较新时间戳，不猜测，也不删除临时文件。

这一流程不写入 NTFS 设备，不清除 dirty，不授权重新挂载，也不意味着日志可以回收。调用方仍需隔离设备访问，正式设备租约尚未接通。密钥与状态仍依赖独立 root 私有目录，不能抵抗 root 或整个系统盘回滚。

## 可重复中断

恢复在替换前失败，仍保留旧快照与临时快照，可重新进入恢复模式核对；在替换后失败，重新打开会读取已经发布的快照。任何本次失败都会锁住当前实例，不能将“可能已经完成替换”报告成明确未执行。

覆盖了恢复替换前、替换后、目录持久后抛错及实际子进程退出，然后重新打开和检查块日志。未覆盖实际硬件断电、磁盘缓存违约或生产 root 服务重启。

## 245 项真实引擎矩阵

在上一轮 149 项基础上新增 48 个凭据发布中断场景，每个场景同时核对普通检查拒绝及显式恢复成功，共增加 96 项检查：文件/目录、4 KiB/16 KiB 缓存块、每类 6 个创建写入点，分别在凭据临时文件写完和持久刷新后立即退出。

恢复凭据前后，镜像内容摘要必须保持一致；恢复后严格检查日志通过，再交给测试专用 Python 规划器回滚整个隔离事务。要求完整镜像恢复到起始摘要、独立哨兵文件回读一致、干净可写重新挂载通过。共计 168 项故障恢复、72 项严格拒绝及 5 项正常/提交后中断检查。

这仍是普通文件承载的 64 MiB 独立 NTFS 镜像，事务覆盖干净挂载到干净卸载；不是生产端原生恢复执行器或持续挂载事务恢复。原有四个无日志 MFT/MFTMirr 失败镜像及 qsw 2 TB 硬盘未修改。
