# 后台密钥与可信凭据存储验收

日期：2026-09-25。新增 `BlockJournalAuthority`，替换真实引擎隔离测试中原有的简化凭据存储。43 项专项及现有核心包 179 项测试通过；真实引擎的 125 项场景已通过，最终源码报告记录于本轮交接文件。本组件尚未安装或接入运行中的 root 后台、FSKit 操作入口，不代表正式后台接通完成。

## 实现与边界

- 正常构建只提供固定的 `/private/var/db/volisle/block-authority` 入口，要求实际和有效用户均为 root。沿路径逐级打开目录，不跟随符号链接，检查祖先所有者和可写权限；最终目录必须为所有者私有的 `0700`。逐级创建后的目录项刷新后，才初始化密钥/状态。当前 helper 尚未调用该入口。
- 对真正空目录生成 32 字节系统随机密钥，独占创建 `0600` 普通文件，执行文件/目录刷新。已有目录必须同时存在合规密钥及认证状态；密钥丢失、长度错误、状态丢失或不匹配时拒绝，不生成替代密钥。没有实现在线轮换、备份恢复或密钥跨进程传递。
- 凭据按事务 UUID 保存，绑定卷身份、引导区摘要、设备容量与块大小；更新必须匹配原凭据，序号只允许递增一。重复创建、旧序号、跳号、身份改变、无效认证值都拒绝。重启后可枚举已记录的绑定，供后续恢复协调器核对；枚举本身不授权恢复。
- 状态快照使用独立域的 HMAC-SHA256 认证，和块日志的认证域不同。写新临时文件并持久刷新，重新核对原状态和文件身份后原子替换，再刷新目录/文件，最后才返回成功。返回失败不能据此断定未保存，调用方必须重新核对。
- 持有目录排他锁；读写检查文件所有者、权限、类型、链接数、长度和目录内名称与打开 inode 的一致性。运行中状态或密钥被修改、目录改名会失败并锁住组件。未知文件或崩溃遗留临时文件保留并拒绝打开，不自动删除证据。
- 最多保留 256 个事务凭据，状态文件最多 512 KiB，序号上限与块日志一致。容量满时拒绝新增，保留旧凭据。这仅限制凭据存储，**不是全部块日志的磁盘配额**；安全回收/退役协议尚未实现，不能据此宣称支持无限期运行。

信任基础是独立 root 私有目录。状态认证不是加密，也不能防止 root 同时恢复旧密钥与旧状态，或整个系统盘被回滚。当前没有硬件单调计数器或外部可信见证。内存释放不声称能保证 Swift `Data` 的全部副本清零。日志仍含原始块内容，未来跨进程方案不能把密钥直接交给任意调用方。

## 43 项专项

`scripts/test-block-journal-authority.swift` 验证随机密钥持久保存、不同存储实例生成不同密钥、独占租约、重启后凭据与身份枚举；密钥/状态缺失、截断、过大、篡改、软/硬链接、权限放宽、目录或祖先符号链接；重复/过期/跳号/错身份更新、无效绑定、容量耗尽保留旧状态、运行中改动、关闭后拒绝访问。

五个写入阶段分别注入抛错，核对不返回成功。四个阶段使用子进程直接退出：替换前遗留临时文件的情况拒绝重新打开；替换后的状态可认证读回。它们不等同于硬件断电或磁盘缓存失效测试。

专项还把真实凭据组件接入 `BlockJournalTransaction`：完整块写入前检查外部凭据已经保存，提交后关闭并重新打开，再用持久密钥和凭据检查块日志。非 root 调用正式入口明确拒绝。本机测试未请求管理员权限、未创建系统存储目录；测试目录入口仅存在于 `VOLISLE_BLOCK_JOURNAL_TESTING` 构建中。

先用未实现骨架观察随机密钥测试失败，再完成实现；重启身份枚举也先验证空实现失败。证据：`red.log`、`red-bindings.log`。专项报告见 `.workbench/block-authority-d15923f5-472a-40da-8565-66f1ce3b8dfb/result.json`。

## 真实 NTFS 引擎链路

`scripts/test-block-transaction-engine.py` 和对应 Swift 驱动已改为使用本组件及每个隔离存储实例的随机密钥，不再使用旧的固定测试密钥或简化 `Anchor`。编译当前 C 桥接、原生完整块写入组件、认证日志、事务协调和凭据存储；全部构建在本机完成。

同一 125 项矩阵覆盖 4 KiB/16 KiB 块、文件/目录创建、每类 6 个实际写入点：5 项正常/提交后中断；96 项可认证的故障回滚，核对整镜像恢复摘要、独立哨兵回读和干净重挂载；24 项凭据落后于日志的情况拒绝检查并保持镜像不变。

恢复仍为测试专用 Python 规划器；事务仍覆盖干净挂载到干净卸载。它不替代持续挂载会话的逐操作恢复，也不清除产品的 MFT/MFTMirr 中断发布阻断。测试没有安装扩展，没有操作 qsw 硬盘，也没有改动早前失败镜像。
