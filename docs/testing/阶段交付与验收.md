# 阶段交付与验收

2026-09-19 初始报告；后续增量记录按日期覆盖下面的早期状态。本报告按实际证据区分完成、原型、未验证和阻塞。

2026-09-20 最新进展：Apple 标识注册、Developer ID 测试包签名安装及 FSKit 系统加载已通过；一次性镜像上的 Finder 复制、系统读写、正常卸载、独立哈希和分配检查、只读重挂已通过。测试期间发现并修复缓存范围重叠导致的重复分配；失败样本保留。核心测试已扩充至 41 项，桥接 21 组。完整证据与剩余边界见 [FSKit 镜像写入与 Finder 验收](2026-09-20-FSKit镜像写入与Finder验收.md)。下文早期的“未验证”不代表这些后续样本仍未运行，但真实盘写入、Windows 检查、异常恢复和最终产品验收依然未通过。

后续属性增量：创建/设置属性预校验、消费结果回报及 100 ns 时间戳已接入，新增时间写入故障检查通过；两份新镜像分别通过 18 项、19 项系统检查，后一份含 Finder GUI。详见 [文件属性与精确时间验收](2026-09-20-文件属性与精确时间验收.md)。覆盖式保存仍拒绝，未把多步改名宣称为原子操作。

后续改名增量：修复同名改名，补齐目标冲突与 inode 祖先链预检、关闭错误及同步边界，取消失败后删除新名称的回滚。7 个写入失败点、2 个同步失败点和 7 个整块写后进程退出点通过；系统镜像验证打开文件的改名、父目录移动和删除后读写，100 份文件独立校验通过。见 [改名故障与打开文件验收](2026-09-20-改名故障与打开文件验收.md)。这不是扇区撕裂、断电或覆盖替换验收。

后续替换增量：开发测试库新增保留旧版本的替换原型及外置计划驱动的只读内容导出。14 个写失败、4 个同步失败、14 个完整写后退出点均保留新旧内容；全部异常样本只读导出通过，镜像哈希和 dirty 不变。默认/FSKit 构建关闭该实验接口，未接入覆盖保存；打开目标的稳定身份和副本回收仍待完成。见 [保留版本替换与只读恢复验收](2026-09-20-保留版本替换与只读恢复验收.md)。

后续对象身份增量：文件引用含 MFT 记录号与序列号，按引用读写/查属性，路径操作先核验身份；缓存区分同一路径的新旧对象，旧对象回收不驱逐新对象。7 组桥接引用检查与原生缓存测试通过，系统镜像 19 项及 100 文件核验通过，已安装最新默认只读版本。覆盖保存仍拒绝；后续写入会改变旧版本哈希，恢复记录和副本清理仍需独立设计。见 [稳定文件引用与对象生命周期验收](2026-09-20-稳定文件引用与对象生命周期验收.md)。

后续恢复记录增量：原生组件已实现追加校验链、修改前意图、写后指纹更新、当前会话回收门禁及两次身份核验后清理，记录失败可终止 NTFS 写会话并保留 dirty。普通镜像 32 个场景通过，包含 14 阶段退出、6 个清理写失败及 6 个写后退出点；只读导出区分匹配、不匹配和缺失。组件未接入 FSKit 替换/回收回调，安装版本保持只读。见 [恢复记录持久化与受控清理验收](2026-09-20-恢复记录持久化与受控清理验收.md)。

## 阶段 0：可行性（局部完成）

完成：商业 SDK、NTFS-3G + macFUSE FSKit、NTFS 核心直接适配 FSKit 三条路线与取舍；许可证来源；本机工具链与 FSKit SDK 类型检查；隔离源码构建与离线镜像实验。来源与固定版本见 `docs/feasibility/技术可行性报告.md`。

证据：`docs/testing/ntfs-image-result.json`。新建 64 MiB NTFS 镜像、4 类文件写读 SHA-256、根目录枚举通过。镜像已清理，没有实际设备写入。源码包与上游 SHA-256 一致。

未覆盖：Finder 挂载、改名移动删除、卸载重挂、Windows 读取 / chkdsk、故障注入。没有演示成功冒充验证。2026-09-20 用户改为免费开源优先、后续 Mac App Store 收费；商业 SDK 不再是研发前置条件。当前剩余项为开源桥接审计、真实 FSKit 接入和权限配置、指定测试介质及 Windows 环境。下一步审计固定提交并做隔离验证，见 `docs/product/开源与商业化规划.md`。

## 阶段 1：基础客户端（部分完成）

完成代码：SwiftUI NavigationSplitView、物理设备分组及卷列表、系统真实挂载状态与容量、Finder 入口、菜单栏、外观偏好、诊断主动导出。Disk Arbitration 监听出现/消失/描述变化；手动刷新重新读取。核心模块不调用 shell、不修改磁盘。

证据：`swift build --package-path apps/macos` 和本地 release 开发包构建通过；`VolisleProbe` 真实只读运行，得到 1 个外接设备分组、2 个卷（APFS 系统可写 / EFI 未挂载），容量与稳定身份存在。无 NTFS 设备接入，因此 NTFS 发现不能从 APFS 结果推断通过。

UI 证据边界：最初仅完成进程启动，自动化因缺少 Bundle ID 受阻。2026-09-20 已使用仅添加临时测试标识的隔离副本补测，确认可执行文件与开发包 SHA-256 一致；完成主窗、设置、诊断首次/重复打开、文本与 JSON 实际导出及取消、深色设置和诊断显示，并修复空白弹窗、Logo 加载及设置外观问题。测试进程和临时副本已清理。菜单栏专项操作、Finder 打开、VoiceOver 全流程与跨系统 GUI 尚未验收，详见 `docs/testing/2026-09-20-基础版增量验收.md`。

演示：原生应用不注入假磁盘。官网中的应用画面是独立 UI 原型，紧邻标明示例数据。

未完成：启动登录、按卷自动挂载、完整英文翻译、上述剩余原生 GUI 测试、睡眠唤醒和热插拔硬件复核。当前没有写入权限申请，不测试或宣称权限撤销恢复。

## 阶段 2：读写闭环（阻塞）

完成基础：VolumeIdentity、挂载状态、安全策略、结构化错误、FileSystemAdapter、UnavailableEngine、MountCoordinator actor 与 VolumeResolver 合约。设备级互斥、调用前二次身份读取、未知风险拒绝写入。适配器契约要求持有真实设备句柄后再次核验。

验证：首批 12 项测试已在 2026-09-20 扩充为 **19 项 Swift Testing 测试通过**，其中风险拒绝测试含休眠/dirty/日志三个参数用例。测试数据仅测试目标可见。覆盖：清洁外接卷门禁、未知风险、风险拒绝、内部/系统卷、BSD 编号复用、UUID 缺失、非 NTFS、引擎不可用、同设备互斥及失败解锁、检查期间磁盘替换、诊断输出隐私约束。新增引擎检查顺序、风险重新核验和非空诊断样本见 `docs/testing/2026-09-20-基础版增量验收.md`。

限制：这些是纯策略 / 测试替身验证，**不是 NTFS 风险检测或真实挂载实现**。协调器尚未连接生产 resolver 或 UI 写入入口。唯一产品引擎明确返回不可用。真实超时、取消、设备忙、多卷卸载及拔盘后的系统状态均未验收。

下一步：引擎固定版本与许可证审查后，实现实际设备句柄核验、风险检查和非强制卸载；严格在指定可丢弃介质完成全部端到端清单，之后才开放按钮。
