# 恢复记录持久化与受控清理验收

本轮新增原生 `ReplacementJournal`，完成宿主恢复记录、写后指纹更新、当前会话内的清理门禁，以及基于最新已完成记录的只读导出。组件已在普通 NTFS 镜像中连接真实桥接操作验证，**尚未连接 FSKit 的覆盖保存和对象回收回调**。

## 实现

记录存放在新建的私有宿主目录中：目录权限 0700、文件权限 0600，每个事件使用独占创建的编号文件。记录包含版本、顺序、前项摘要、事件内容和 SHA-256 校验值。写完整事件并同步文件、目录后，才允许对应 NTFS 修改继续执行；NTFS 修改及同步完成后，再追加完成事件。

状态顺序：

`prepared → replace-intent → published → write-intent / write-complete → reclaimed → cleanup-intent → cleaned`

- 起始记录绑定卷序列号、引导记录摘要、源/目标/副本名称、新旧文件引用和内容指纹。
- 旧对象或新对象继续写入时，先记录该对象的写意图；NTFS 同步、读回并计算新指纹后再完成记录。状态中的 `before` / `after` 分别代表旧对象/新对象的**最近已完成指纹**，不一定仍是最初内容。
- 日志追加失败后，本会话持续禁止操作；宿主通过 `nk_abort_write_session` 同时锁定 NTFS 写入，关闭不能把会话错误地标记为干净。接口幂等且不影响只读卷。
- 清理要求当前会话收到旧对象的最终回收通知。一次文件关闭不能替代这个通知；旧对象回收后再次写旧对象会被拒绝。
- 删除前核对副本/目标引用、两份最新内容指纹和源名称不存在；持久化清理意图后再核对一次，然后删除副本并同步，最后记录清理完成。
- 原生组件由调用方串行使用；实际 NTFS 修改与同步由闭包适配器提供，回收通知必须来自受信任的生命周期适配器。当前实验驱动模拟该最终通知，不能算作已验证真实 FSKit 回收时序。

每个事务最多 512 条记录，单条最多 64 KiB，实验指纹文件上限 8 MiB；达到限制会拒绝继续，不覆盖已有记录。当前实现会读回整个受测文件计算指纹，尚未进行生产吞吐量评估。

## 只读重放与导出

已有目录不能重新构造成可写会话；重放结果永远 `cleanupAuthorized = false`，包括记录中已经出现 `reclaimed` 或 `cleaned` 的情况。不清 dirty，不恢复写挂载，也不尝试补做删除。

重放校验连续编号、链摘要、合法状态转移、卷身份、文件类型/权限和链接数量，拒绝残缺记录、缺失中间事件、校验变化、软链接及硬链接。对无效记录只返回诊断用的已验证前缀。

校验链不是数字签名，也不能独立识别整个合法末尾被移走的情况；此时可能读到更早的合法状态。只读重放不恢复清理授权，导出还必须重新匹配文件引用及内容指纹，避免把旧记录当成当前删除依据。

开发工具 `scripts/journal_image_recovery.py` 只接受本项目断开的 64 MiB 镜像。它以只读回调读取内容，仅导出与记录的引用和指纹都一致的数据到新目录；不覆盖已有输出。

- `checkpoint-match`：匹配最近完成的内容检查点，可以导出。
- `checkpoint-mismatch`：例如数据已写完但完成记录尚未写入。保留原镜像，报告未匹配，不伪称该版本已验证恢复。
- `unavailable`：该角色不在已知路径中或已清理；不导出不相干文件。

无效记录不创建导出目录。有效记录可以只导出匹配的一个版本；报告列明每个版本状态，没有把“导出部分内容”算作完整文件系统恢复。内容仅包含未命名数据流，不包含 ACL、时间和其他命名流。上一轮冻结内容使用的 `ntfs_replacement_recovery.py` 保持原有严格行为，不将其混同为新的记录组件。

## 本地验证

统一命令：`python3 scripts/test-replacement-journal.py`。该命令本地编译原生测试与 C 桥接，只操作新建普通镜像，不 attach。

原生状态/存储测试和宿主终止接口均先出现预期失败，再完成实现。检查覆盖：生命周期顺序、写后指纹、未回收拒绝、过期证明拒绝、持久化失败后不调用修改闭包、不恢复失败会话、已有事务不能重用、损坏记录及链接拒绝。记录文件真实独占创建冲突用于触发持久化错误，并非仅模拟一个成功返回值。

真实 NTFS 镜像 **32 个场景通过**：

| 场景 | 数量 | 检查 |
| --- | --- | --- |
| 正常替换、继续写新旧对象、回收及删除旧副本 | 1 | 新旧指纹按写入更新，副本清理，新版本和无关哨兵正确 |
| 清理前身份变化、清理意图后身份变化 | 2 | 原旧文件和占用副本名称的不相干文件均保留；不误删 |
| 替换意图、写入完成、清理完成的宿主记录失败 | 3 | NTFS 写会话锁定，关闭报错且 dirty 保留 |
| 14 个持久化阶段后进程立即退出 | 14 | 记录重放得到预期阶段；不恢复删除授权，dirty 仍在 |
| 清理的每个底层写入回调分别失败 | 6 | 新版本完整、哨兵不变，会话锁定 |
| 清理的每个完整写入回调后进程退出 | 6 | 同上；退出后不自动补做清理 |

文件覆盖非驻留数据：旧文件 16 KiB + 11 字节，新文件 32 KiB + 11 字节，继续写入仅改变前 11 字节，尾部独立核验。异常后的路径内容使用独立上游 `ntfscat` 检查。所有有效记录场景还执行只读检查点导出；中断写入不匹配与副本缺失分别回报，导出内容按固定测试字节验证。镜像全量哈希前后相同、零写回调通过。

正常清理后，独立分配检查覆盖 21 条 MFT 记录和 646 个占用簇，未发现所检查的区段重叠或分配位图不一致。这不是完整 NTFS 检查。

证据：`replacement-journal-suite.json`、`replacement-journal-result.json`。临时镜像、宿主记录和导出在测试完成后清理；结构化结果保留。
