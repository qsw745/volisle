# 只读预检与恢复健康约束验收

日期：2026-09-25。

## 实现

本轮为 FSKit 挂载前预检与隔离恢复流程加入共用的 `NTFSReadOnlyInspection`。它包装现有 `nk_inspect`，提供只读、受读取预算限制、读取错误不可被忽略的回调上下文。

- 始终设置只读描述符，不提供写入或刷新回调。回调对象只在同步检查期间存活，虚拟恢复视图不会被保存供检查结束后使用。
- 单次读取最多 1 MiB、累计逻辑读取请求最多 128 MiB、最多 32768 次请求；支持较小的显式预算。拒绝负偏移、负长度、越界、整数极值、空缓冲区和无效设备大小。
- 任何短读、超长返回、底层错误或预算耗尽都会使本次检查持续处于失败状态。即使引擎随后返回 CLEAN，也向上层返回 UNKNOWN，不能把未完成的检查当作通过。
- `NTFSVolume.inspectBeforeWritableActivation` 已在源码中改用该适配器，继续通过 FSKit 资源的已有对齐读取函数访问设备。
- 隔离引擎在创建日志/可信凭据目录前检查初始状态；在原生回滚器的虚拟恢复视图和刷盘后的设备视图中再次检查；正常提交检查点及恢复完成记录中断续办也核对预检状态。
- 基线摘要继续使用独立镜像摘要。摘要相等和挂载预检通过是两个条件，不能互相替代。

此检查沿用已有引擎对 dirty、休眠和 NTFS 日志安全状态的判断，以及只读打开时的基础元数据校验。它是挂载安全预检，**不是完整 NTFS 一致性扫描或修复工具**。读取预算限制的是传给读取回调的逻辑请求量，不是物理 I/O 总量、执行时间或引擎内部全部内存分配。

## 验证

**23 项边界专项、366 项真实 NTFS 镜像检查、179 项核心测试（21 组）通过；默认和日常写入扩展两种本地构建及入口核验通过。**其中 366 项包含 8 项实际只读适配器检查，不能再额外累计。

引擎报告：`.workbench/block-journal-39blzvl6/result.json`。干净隔离镜像本次预检发出 30 次读取请求，这个数字不代表大容量磁盘或其他卷的读取上限。

专项验证正常数据复制、只读能力边界、各检查状态传递、各种非法范围、短读/长读/抛错、累计字节与次数上限，以及引擎吞掉读取失败后仍返回 CLEAN 的情况。

真实 NTFS 用例沿用此前完整创建/回滚/凭据/日志池矩阵，新增：

- 干净镜像用真正的 `nk_inspect` 检查；首次、中途和末次底层读取分别注入错误及短读，再验证小预算拒绝，镜像保持不变。
- dirty、休眠、MFT 镜像记录损坏分别在创建日志状态前被拒绝。
- 测试专用入口故意为上述异常镜像登记一个完全匹配的基线，验证恢复仍被拒绝，镜像与可信凭据均不变，没有发布恢复完成记录。这个注入入口只存在于隔离驱动，不在扩展或后台服务中；驱动限制为新建测试目录内的 64 MiB 普通文件。

第一次编译虚拟恢复视图适配时出现 Swift 非逃逸回调与存储式上下文的类型约束。已把公开检查接口保持为同步、非逃逸调用，并用有界生命周期适配内部 C 回调。最终验证使用修正后的代码。

结果和报告路径保存在 `.workbench/checkpoint-health-20260925/handoff.json`，源码及两个独立扩展二进制摘要见 `source-hashes.json`。修复前边界专项失败保留于 `red.log`；首次编译失败记录保留于 `engine.log`，真实引擎最终结果使用 `engine-final.log`。
