## 本轮发现并修复的问题

1. **2 TB 盘写入极慢**（构建 4 已存在）：每次查询剩余空间都重新扫描约 61 MB 的簇位图。改为每次挂载只扫描一次，之后使用引擎的增量计数；新增 `test-statvfs-incremental.py`，增量值与重新挂载后全量统计一致。
2. **I/O 粒度过小**：每 4 KiB 同步直写，原内容逐块同步读取，每个操作都刷设备。改为延迟写入、检查点统一刷新，原内容批量直读，缓存块改为 64 KiB。日志矩阵扩展到 64 KiB 块，共 717 项通过。
3. **应用内无法保存**：0600/0700 权限请求被拒、同名替换不支持。改为与 macOS 处理 exFAT 相同的方式，只持久化 NTFS 能表达的只读位（卷以 `noowners` 挂载，本来就没有 Mac 多用户隔离，不放宽任何现有访问）；同名替换在单个 FSKit 操作内完成，由写入日志保证崩溃原子性。
4. **Mac 新建文件权限为 Everyone 完全控制**：改为按父目录可继承 ACE 生成（ntfs-3g `ntfs_inherited_id`，所有者取父目录）；同名替换时复制原文件的完整安全描述符（与 Windows `ReplaceFile` 一致）。
5. **Windows 系统隐藏目录显示在 Finder 中**：NTFS 隐藏属性映射为 `UF_HIDDEN`。
6. **拒绝读写时提示错误**（显示“无法核对当前磁盘，请检查连接”）：后台读取 `mount` 返回的扩展拒绝原因，区分脏标记 / Windows 休眠 / 未安全弹出，并给出处理方法。
7. **拒绝读写后设备被占住、无法推出**：FSKit 在激活失败后仍在扩展进程中保留设备描述符（`revoke()` 不释放）。激活被拒后该单设备实例延迟 2 秒退出；镜像实测拒绝后可直接推出。
8. **界面**：侧栏只列 NTFS 盘；技术操作收入“高级”子菜单；单卷设备推出不再二次确认；去掉“覆盖保存尚在适配”等过时文案。

## 第 2 次物理拔线（构建 7 → 构建 8，22:01）
