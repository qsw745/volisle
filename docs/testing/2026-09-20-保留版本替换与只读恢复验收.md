# 保留版本替换与只读恢复验收

本轮实现了**保留旧版本的替换原型和只读内容导出**。它不是 POSIX 原子替换，不接入 Finder 覆盖保存，也不修改或修复异常 NTFS 卷。已安装的测试应用保持上一轮默认只读版本。

## 替换原型

`nk_replace_preserving` 只在独立开发测试库定义 `NK_EXPERIMENTAL_REPLACEMENT` 时启用，且只接受 64 MiB 回调卷。FSKit 构建不定义该宏；实测默认编译分支在可写镜像上返回 `ENOTSUP`，没有替换写入回调。

操作限定为同一规范目录内的两个受支持、单链接普通文件。修改前检查全部名称、路径长度、源与目标存在性、文件类型、源目标 inode 和恢复副本名称冲突。恢复名称还按卷的 Unicode 大写表检查所有目录项和 DOS 别名；测试曾复现仅依赖普通路径查找时，POSIX 命名空间允许大小写不同的冲突名称，现已拒绝。

顺序如下：

1. 调用者先将恢复计划写在镜像之外，记录卷序列号、引导记录摘要、三个候选路径以及新旧内容的长度与 SHA-256；独占创建并同步计划及其父目录。
2. 将旧目标改名为尚不存在的恢复名称。普通改名先同步新链接，再删除旧名称并同步。
3. 将源文件改名到目标位置，沿用同样的同步顺序。
4. 成功后保留旧版本，**不自动删除恢复副本**。中途错误保留剩余名称，锁定会话并维持 dirty；不做破坏性的回滚。

这是内容保留协议，两个改名之间目标名称可能不存在。C 接口的外置计划是调用方合约；开发测试遵守该合约，C 本身不保存或检查计划。不能直接把该函数当作 FSKit 的 `rename(overItem:)` 实现。已打开旧目标的对象身份、句柄和缓存处理，以及恢复副本何时可以清理，仍需独立实现。

## 只读恢复工具

`scripts/ntfs_replacement_recovery.py` 仅接受 `.workbench/volisle-replacement-*` 内已断开的 64 MiB 普通镜像，拒绝链接、设备路径和已连接镜像。恢复计划和新建输出目录必须位于同一实验目录。单个候选文件上限 8 MiB。

工具以只读回调打开镜像，按预先记录的长度和哈希识别两份内容，导出固定名称 `before.bin`、`after.bin` 及 `recovery.json`。源卷保持原样，不执行写挂载、清 dirty、修复、名称回滚或副本删除。检查失败不创建导出目录；已有输出和软链接不覆盖。镜像全量哈希前后相同、零写回调均纳入验收。

这只导出未命名数据流，不是完整文件元数据备份，不保留 ACL、时间戳和其他命名流。恢复计划也不是防篡改签名；它的身份与摘要用于防止选错卷或导出错误内容。

## 本地验证

运行 `./scripts/build-ntfs-bridge.sh` 和 `python3 scripts/test-ntfs-replacement.py`。测试创建并清理普通镜像，不 attach，也不使用真实硬盘。

| 检查 | 结果 |
| --- | --- |
| 默认编译分支关闭实验接口 | `ENOTSUP`，替换零修改 |
| 正常替换 | 目标为新内容、旧内容保留在恢复名称、源名称移除 |
| 名称、路径、目录、目标缺失和冲突 | 修改前拒绝，原内容不变 |
| 只读卷 | `EROFS`，零写回调 |
| 嵌套目录、中文与 Emoji、驻留小文件和空文件 | 替换及新旧内容导出通过 |
| 错误序列号、目录穿越、重复名称、错误哈希、非法长度、已有输出、软链接 | 拒绝且源镜像不变 |
| 第 1–14 个写回调分别失败 | 报错、会话锁定、dirty；两份内容及无关哨兵完整 |
| 第 1–4 个同步点分别失败 | 同上 |
| 第 1–14 个完整写回调后测试子进程退出 | dirty 保留，再次写挂载拒绝；两份内容和哨兵完整 |
| 全部 32 个异常样本的只读导出 | 新旧导出均与预期字节一致，镜像哈希不变，dirty 不变 |
| 正常替换后独立分配检查 | 23 条 MFT、765 个占用簇，未发现所检查的重叠或位图不一致 |

新测试先在未实现接口和未实现恢复工具上出现预期失败，再通过实现。原始结果：`ntfs-replacement-result.json`。每个异常样本另外用上游 `ntfscat` 独立读取，内容预期来自固定测试字节，不依赖恢复工具自产的预期值。测试临时镜像和导出在完成后清理，保留结构化结果。

回归：核心 41 项、既有桥接 21 组、精确时间 6 项、普通改名故障矩阵通过。默认只读主应用与扩展本地编译成功，生成未签名候选 `apps/macos/build/review-replacement-final`，未安装或公开分发。本轮未重新执行 FSKit 系统挂载或 Finder GUI；此前系统验收不算本轮新增证据。

## 当前边界与下一步

退出测试模拟已经 fsync 的完整写入前缀，没有模拟扇区撕裂、硬件缓存重排或真实断电。没有证明目录索引在全部规模和卷布局上的崩溃一致性；分配检查也不是完整 `chkdsk`。

下一步是为打开的源/目标建立稳定对象身份，验证目标被替换后旧描述符仍读取旧内容、新路径读取新内容，再设计受控副本回收。完成这些之前，FSKit 覆盖入口继续返回不支持。跨 Windows 回读与检查、物理持久化和真实产品验收仍未完成。

本轮环境复核见 `replacement-environment-result.json`：已安装版本保持 `signed-rename-readonly`，严格签名校验与可执行文件哈希核对通过；无实验镜像连接或 Volisle 挂载，用户 2 TB `qsw` 仍为只读。本轮没有向用户盘写入或更改已有内容。
