# BitLocker 读写（2026-10-05）

## 设计

- 引擎（`packages/VolisleNTFS/bridge/bitlocker.inc`）：解密视图在底层可写时可写，写入按扇区就地加密（XTS 与 CBC），部分扇区先解密合并；读写按连续区段批量。BitLocker 元数据块与卷头存放区拒绝写入（EIO），跨边界整体拒绝、零写入。四种加密卷的这些区域都由 `System Volume Information/FVE2.*` 文件占用，NTFS 不会分配。
- 扩展：带 `volisle-rw` 时与普通盘走同一套写会话。写入日志记录底层密文，回滚不需要密钥；恢复与写入前预检通过 `JournaledIO.withVolume` 透过解密视图读取卷标志、日志与引导扇区。日志的空闲空间优化在加密卷上关闭（位图是密文），每块都保留旧内容。没有密钥时恢复拒绝、零写入、保留记录。日志目录按 BitLocker 卷 GUID 前 8 字节命名。
- 后台组件：解锁默认请求读写；扩展因需要检查、休眠或日志不干净拒绝时，自动改为只读挂载并带回原因。
- 应用：显示“可读写/只读”和只读原因；解锁状态下被拔掉的盘留下的挂载（不经过 Disk Arbitration，系统不会移除）在磁盘列表变化时强制卸载。
- 一块普通 NTFS 盘和一块 BitLocker 盘可以同时读写（各自独立的扩展实例与日志）。

## 已知取舍

- 恢复记录保留上限仍是 20 秒或 128 MiB。加密卷每块都记旧内容，128 MiB 在约 30 MB/s 时约 4 秒；qsw 实测硬盘缓存丢失约 48 MB，仍在覆盖范围内。上限受恢复时的内存占用约束，暂不放大。
- “在 Mac 上检查…”不支持加密分区；加密盘需要检查时提示到 Windows 中检查。
- 应用更新前要求没有任何盘屿挂载，BitLocker 盘解锁时更新会推迟，提示“磁盘仍在使用”。

## 实盘（qsw 所在 2 TB 希捷 Expansion，macOS 27.2）

测试分区由 Windows 11 专业版新建并加密：812 MB，XTS-AES 128，密码 + 恢复密钥（`scripts/bitlocker-fixtures/make-qsw-bde.ps1`）。

1. 读写解锁成功，与 qsw 同时读写。
2. 写入 100 MB 随机文件 31.6 MB/s；新建中文文件夹与 5 个文件、追加、复制 Windows 写的 8 MiB 文件（副本哈希与 Windows 计算一致）、改名、删除。
3. 锁定（日志会话正常结束、记录清除），用恢复密钥重新解锁，8 个文件哈希全部一致。
4. 拷贝 200 MB 时强制卸载：会话正常收尾，原有文件完好。
5. 拷贝中强杀扩展进程：重新解锁先回滚到最后一致点，原有文件完好，照常可写。
6. Windows 往返：Windows 用密码解锁，状态“完全加密”、不脏，chkdsk 无问题，8 个文件哈希与 Mac 一致；Windows 写入新文件后交还，Mac 读到且哈希一致、照常可写。
7. 真实拔线（所有者拔线，BitLocker 与 qsw 同时在写）：qsw 自动回滚并恢复读写；BitLocker 旧挂载残留（发现并修复，见上），清除后重新解锁先回滚，原有 9 个文件哈希一致。
8. Windows 中 `fsutil dirty set` 后交还：读写解锁自动改为只读并带回原因 `ntfsDirty`；Windows chkdsk /f 清除后恢复读写。
