# 原生认证块日志存储验收

日期：2026-09-25。本轮新增 `BlockJournalStore` 原生存储组件，进入 VolisleCore 源码。46 项专项场景、现有核心包 179 项测试通过。它仍未连接后台服务或正式 FSKit 写入会话，不是正式自动恢复已完成。

## 已实现

- 调用方提供独立的 32 字节密钥；每条记录用 HMAC-SHA256 认证版本、序号、前一记录认证值和原始载荷。记录绑定事务 UUID、卷身份、引导区摘要、容量与实际块大小。密钥不写入日志。
- 从 `/` 开始逐级 `openat`，不跟随路径中的符号链接；最终目录必须是当前执行用户所有的私有目录。持有目录排他锁，使用独占创建的私有普通文件，拒绝覆盖已有日志。
- 每次追加前后核对打开文件与目录内名称仍指向同一 inode、文件仍为单链接私有普通文件、长度符合预期。运行中删除、改名、硬链接、权限放宽或截断均拒绝。
- 记录包含实际完整缓存块的原字节和新字节，支持短尾块；每次写入后执行 `fsync` 和 macOS `F_FULLFSYNC`。初始目录项也刷新；失败则锁住会话并仅调用一次停止写入回调。
- 单日志默认 64 MiB、4096 条记录，上限可受限配置；单帧最多 4 MiB。解析前检查长度，避免根据不可信长度分配任意大缓冲区。为提交记录预留 **8192 字节的逻辑预算和一条记录名额**，不等同于预分配物理磁盘空间。
- 提交先调用设备刷新，再持久保存提交记录，全部完成后才返回成功。外部设备写入失败时，协调器必须调用 `abort()`；之后即使设备恢复，也不能提交该事务。

HMAC 是认证，不是加密。日志包含块原文，保密性依赖私有目录、文件权限和未来后台存储隔离。代码只验证密钥长度，正式随机密钥生成、保存、轮换与跨组件传递尚未实现。

## 可信最新状态的边界

读取必须同时提供来自日志之外的可信 `BlockJournalSeal`，包括序号和认证值。它用于拒绝截断成历史合法前缀、重放旧记录和尾部状态不确定的日志。HMAC 本身不能阻止把日志与它的旧凭据一起回滚；本组件不从同一日志里自动生成“可信最新状态”。

`record` 成功只说明日志已落盘、内存中的 seal 已更新。正式协调器还必须把新 seal 持久保存到独立可信记录中，完成后才能允许设备写入。记录已持久但回复丢失，或者日志比可信 seal 多出尾记录时，当前检查会拒绝；没有猜测尾部可以丢弃或回滚。这套可信锚点的原子更新、崩溃对账和恢复策略尚未接入后台，不能声称已解决。

## 验证：46 项

测试 `scripts/test-block-journal-store.swift` 直接编译当前存储源码与上一轮的 `MetadataWritePipeline`，测试密钥是公开的固定测试值，从未访问产品钥匙串。

覆盖：正常认证记录与提交、活动写者排斥检查、禁止覆盖旧文件；错误密钥、卷身份、引导区、容量、块大小或事务号；内容改变、截断、合法旧前缀回放、重复记录、软/硬链接、宽松权限；容量/条数限制、非法范围、运行中日志变化、设备刷新失败及失败状态持续。

通过测试专用编译开关注入写入前、写入后、持久化后的故障，确认不返回新的可信 seal。三个实际子进程分别在未提交、已提交、记录写完但未返回凭据时直接退出；重新打开时文件锁已释放，前两者状态符合外部测试凭据，第三种明确拒绝。

与原生块写入组件联合测试验证：日志持久完成后才发生设备写回调；存储容量不足时设备零写入；设备部分写入失败后中止事务、不能提交。后者只在内存测试设备上用已经认证的原字节恢复并核对起点，不是实际 NTFS 卷恢复。

补充覆盖 1 MiB 最大块、512 字节设备尾块、非法零长度/过大帧头，以及日志完成刷新后被改名的拒绝。

## 仍未完成

正式后台的密钥与独立可信锚点提供者、所有日志合计的空间配额/回收、FSKit 逐操作提交协调器、日志恢复执行器、设备身份核验和重新挂载、Windows 跨主机恢复仍未接通。单日志预算不能限制目录中所有历史日志的总空间；这些缺口不能用当前专项通过替代。

本轮没有重新运行或宣称消除了既有四个无日志 MFT/MFTMirr 中断失败，也没有修改 C 引擎、当前安装应用、qsw 2 TB 硬盘或公开下载。发布门禁维持阻断。
