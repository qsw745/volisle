# 后台组件与可信通信验收

本轮完成后台组件的包结构、双向签名校验、状态通信与设置入口。仅有状态查询接口，尚未提供磁盘操作接口，也未注册系统后台服务；不能据此开启主应用写入。

## 实现

- `HelperProtocol.swift` 定义固定服务标识、版本化状态协议、双向签名要求及 5 秒通信超时。要求指定 Developer ID 团队及精确标识，拒绝允许调试的客户端；拒绝 root 或未知审计身份的调用者。调用方另行要求系统服务报告有效 UID 0。
- `HelperService.swift` 在注册前验证主应用、辅助程序签名和封装的启动配置，通过 `SMAppService.daemon` 注册、检查、移除固定组件。系统显示启用后还须实际通信成功，界面才显示已连接。
- `VolisleMountHelper` 仅支持系统服务启动，普通用户直接执行返回 78。协议没有命令、路径、脚本、设备或挂载选项输入。
- 设置入口位于“支持 → NTFS 引擎”折叠区域；普通未签名开发包不可注册。新包将辅助程序和启动配置封装于应用内，先签辅助程序与扩展，再签主应用。诊断程序不进入应用包。

使用 Apple 公开接口。系统服务注册涉及系统设置批准，尚未实测这一生命周期，不能将普通用户测试服务等同于管理员服务。参见 [Apple 服务管理说明](https://developer.apple.com/documentation/ServiceManagement/updating-your-app-package-installer-to-use-the-new-service-management-api) 和 [连接签名要求接口](https://developer.apple.com/documentation/foundation/nsxpclistener/setconnectioncodesigningrequirement%28_%3A%29)。

## 剩余工作

1. 验证系统后台服务的实际注册、授权、连接及卸载生命周期。
2. 接入受限磁盘操作协议：由服务核验实际调用者、持有资源身份、检查卷状态，并完成正常挂载及失败后的只读恢复。必须处理应用退出、连接中断和服务重启后的状态，不能直接向客户端开放命令或任意路径。
3. 验证管理员服务的可移动磁盘权限与用户审计会话；此前的普通用户只读镜像结果不覆盖该路径。
4. 完成实际写入适配器、无 UUID 的 MBR 卷身份策略，以及 Windows、拔插、多 GB 文件和长期压力验收。

主应用依旧使用 `ReadOnlyFSKitEngine`。后台组件显示已连接也不等于磁盘可写；当前版本明确报告写入未接入。
