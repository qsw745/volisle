# 后台组件安装与磁盘身份接口

本轮把已签名后台组件安装到现有测试应用，并通过 `SMAppService` 提交系统注册。当前实际状态为 `requiresApproval`（等待系统授权）；系统设置中的项目名称为 **Volisle Test**，开关关闭。新磁盘检查接口已实现，管理员服务对真实盘的读取尚未验收，不代表写入功能完成。

## 实现与修复

- 新增 `HelperDiskRequest`、`HelperDiskReport` 和固定错误协议。请求仅含版本、BSD 分区名、当前注册表 ID 和容量，不接收任意文件路径、命令、挂载参数或写入选项。请求及响应均限制大小并验证对应磁盘身份。
- 服务端重新通过 Disk Arbitration 和 IOKit 读取设备信息，仅接受外接 USB 分区。检查当前挂载状态，拒绝已有可写挂载或其他驱动挂载，然后以 `O_RDONLY | O_NOFOLLOW | O_CLOEXEC` 持有块设备句柄，读取一个设备块中的 NTFS 引导标识和前 512 字节摘要，再次验证身份与挂载状态并关闭句柄。只返回摘要，不返回磁盘内容。
- 读取接口明确返回 `fileSystemHealthChecked=false` 与 `writeAccessAvailable=false`。引导标识检查不能代替 NTFS 脏标记、休眠或日志检查，不能用作写入许可。
- 新增固定支持命令 `--helper-status`、`--helper-register`、`--helper-unregister` 和 `--helper-inspect`，复用设置界面的签名校验和服务控制逻辑；没有 sudo 或通用 shell 接口。
- 修复首次注册入口：实际安装时，完整签名包对应的系统后台记录不存在，macOS 返回 `.notFound`。旧界面误显示“需完整签名安装版”且无法设置。现在只有包校验通过时才允许首次注册；已启用或等待批准的服务不重复注册。注册返回需要批准时保留可操作的批准状态。

## 批准后的下一步

本轮已请求用户在 macOS 系统设置批准 **Volisle Test** 后台组件。此操作是新系统组件的批准，不是重新启用已启用的“盘屿 NTFS”文件系统扩展。

批准后先验证真实 root 服务连接，再执行 `.workbench/helper-device-20260922/verify-physical-readonly.py`。该本轮专用验收脚本固定已授权 qsw 的设备、注册表 ID、容量、既有引导摘要及安装版本，先检查服务就绪，再验证错误身份拒绝和正确身份读取。脚本没有卸载、挂载或写入步骤；当前仅完成语法检查，尚未执行。若用户重新插拔或更新了应用，应先核对新状态，不得直接放宽脚本绑定。

后续仍需接入挂载操作的服务端持久状态、异常恢复和实际写入适配器，再做 Windows、拔插、大文件与压力验收。主应用仍使用 `ReadOnlyFSKitEngine`。
