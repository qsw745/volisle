# 覆盖安全描述符与发行源码集中验收

## 本轮范围

集中处理三个实际缺陷及本地回归：实验覆盖保存的 Windows 权限保留、发行二进制与对应源码的绑定、重新连接后失效的拔线提示。没有在 qsw 上实验新代码，没有开放日常覆盖保存；正式剩余项统一见 `../release/正式发布状态.md`。

## Windows 安全描述符

失败复现：给目标文件设置不同于临时文件的所有者 SID 和带拒绝条目的 DACL，执行现有覆盖后，目标文件继承临时文件的描述符，测试明确失败。日志：`.workbench/release-completion-20260924/security-red.log`。

修复：在改名发布前读取并完整保留目标 Windows 安全描述符，包含 owner、group、DACL、SACL 和控制位；保留的旧 inode 不改动。新描述符持久化并重新读取逐字节核对后才发布。已有描述符一致时不执行冗余修改。

不能直接依赖上游通用 getter：上游遇到缺失/损坏描述符会构造一个最小权限值。新实现对旧式属性及 `$Secure:$SDS` / `$SII` 分别严格检查边界、标识、长度、描述符及摘要，失败阻止发布并封锁后续写入。没有把 SID 转换为 Mac UID，也不宣称提供跨系统身份映射。

`scripts/test-replacement-security.py` 通过：4 类成功场景（自定义所有者/拒绝 DACL、SACL、空 DACL、旧式描述符），1 项无效 security ID 拒绝，14 个块写入失败点、5 个同步失败点、14 个写回调后进程中断点。故障后新旧内容和旧 ACL 保留；已发布新文件必须拥有目标 ACL，无关哨兵文件不变，失败卷拒绝重新读写挂载。

证据：`.workbench/replacement-security-iu1flqth/result.json` 和 `.workbench/release-completion-20260924/security-final.log`。测试夹具工具 `scripts/fixtures/ntfs-security.c` 仅处理 64 MiB 普通镜像，不链接进 App。

此证据不代替 Windows 自定义 ACL 实盘往返、目录继承、Mac 非所有者隔离或实体断电测试。

## 对应源码

之前的候选打包脚本在打包时收集工作区源码，未证明这些源码与更早的二进制对应，而且未打入 `LICENSE_SCOPE.md`。新增 `SourceProvenance.json`，在候选编译期间捕获源码/资源/许可及文件模式，并在签名前放入 App。打包前必须与此记录一致；实际生成的源码归档也逐项检查内容、模式和条目集合。

构建依赖使用固定摘要的 NTFS-3G 归档，核对展开源文件并在本地清理重编译，避免旧静态库与新源码配对。此机制是构建输入与交付配套验证，不宣称二进制逐字节可重现。

`scripts/test-source-provenance.py` 已由缺少门禁的失败转为通过，包含源码/许可变化、额外文件、可执行位改变、链接、无效记录和目录越界的拒绝。旧候选没有签名内清单时拒绝打包，必须重建。日志：`.workbench/release-completion-20260924/provenance-red.log`、`provenance-green.log`。
