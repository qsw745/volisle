# 自动日志维护与新事务接续验收

日期：2026-09-25。

## 本轮实现

上一版日志回收和批次切换需要调用方逐步执行，记录或文件额度耗尽时，新事务会被拒绝。本轮增加统一的新事务准备入口：先检查请求，再检查日志池，回收已有可信完成记录授权的日志，全部事务已结束时切换批次，最后生成属于新批次的事务身份并创建日志。后续调用方不必自己安排“回收 → 切换 → 生成身份”的顺序。

- `BlockJournalAuthority.prepareTransaction` 统一准入、维护、身份分配和事务创建。清理发生在新身份分配之前，避免清理切换批次后，刚发出的身份立即过期。
- `maintainCompletedTransactions` 可在串行空闲点执行，返回删除数、已经不存在的数量、未结束事务数和是否切换批次；它不操作设备，不作设备健康判断。
- 新的目录清单校验持有可信池独占锁，核对每个日志必须归属已知凭据，且未结束事务必须保有对应日志。初始化写日志后、发布首凭据前中断所留下的未知日志会阻止新事务，不会被自动删除。
- 已独立完成核对的正常提交和回滚均可回收。日志回收继续逐个认证内容；混合池可释放已完成日志，但保留未结束日志及其批次凭据。
- 全部事务安全结束后，原有空池核对与原子批次切换继续适用。旧事务身份继续拒绝。未知文件、损坏终态日志、池被替换、锁冲突、缺失未结束日志都停止处理。
- 无效参数、同卷未结束事务和超出整池容量的新请求在清理前拒绝；失败回调只调用一次。中断可能已持久完成部分清理，必须重新打开核对并续办，不凭返回失败倒退磁盘状态。
- 不自动推断恢复完成、不清除 NTFS dirty、不放宽预算，不因空间不足而丢弃未完成事务。

串行空闲点检查依赖调用方设备保护；日志池独占锁不等于物理磁盘独占访问。这些入口目前接入隔离真实引擎驱动，尚未由已安装的后台服务或 FSKit 调用。

## 测试

最终源码：**24 项自动维护专项、338 项真实 NTFS 镜像检查、393 项相关回归、179 项核心测试（21 组）全部通过**。相关回归包含此前 363 项和可信日志池 30 项。

专项报告：`.workbench/managed-2c683b19-c355-4a41-99db-97dd98c60e5a/result.json`。真实引擎报告：`.workbench/block-journal-_7m2heij/result.json`。首轮 `engine.log` 保留为历史结果，最终验收使用 `engine-final.log`。

专项包括单条凭据容量下 32 次交替“提交结束 / 回滚完成”及逐次进程内关闭重开；无需手动退役或切换即可接续事务。另测幂等维护、混合活动/结束日志、未知内容、丢失活动日志、损坏日志、池锁/替换、无效/超额请求、八个维护持久化阶段进程退出，以及被回调吞掉的重入错误。

真实 NTFS 驱动新增自动准入路径，原 300 项检查保留。新增正常提交与回滚两种前序结果，各覆盖正常维护及八个退出点，然后直接开始新的实际创建、独立只读核对旧/新文件及 sentinel；不手动调用退役或批次切换。另验证活动事务和仅写入提交日志、尚未独立核对的事务会阻止新写入，整镜像摘要和凭据保持不变。

用例使用新建的 64 MiB 隔离镜像；专项完成回调是受控夹具，不计为独立生产检查点验证。真实引擎用例继续使用隔离镜像的完整摘要及只读 NTFS 核对，事务范围仍为干净挂载至干净卸载。

最终数字与报告路径保存在 `.workbench/managed-journal-20260925/handoff.json`，源码摘要保存在同目录 `source-hashes.json`。修复前证据为 `red.log`（原入口容量耗尽）、`red-orphan.log`（未知日志未拦截）、`red-reservation.log`（超额请求先清理后失败）。
