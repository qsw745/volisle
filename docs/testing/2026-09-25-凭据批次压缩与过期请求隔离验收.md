# 凭据批次压缩与过期请求隔离验收

日期：2026-09-25。

## 结果

原生可信凭据支持按批次安全释放。仅当当前全部事务都已持久结束，并且选定可信日志目录已经回收为空时，才能持久切换到新批次并清空旧明细。旧请求保留旧批次标识，会在查找事务 UUID 之前被拒绝，因此清空明细不会把旧事务误认为新事务。

42 项新专项、300 项真实 NTFS 镜像检查、321 项相关专项回归和核心包 179 项测试通过。容量限定为 2 条的专项连续完成了 260 次事务、130 次批次切换和重新打开；没有通过调大上限来绕过问题。

本轮没有操作 qsw、真实设备或此前故障镜像，没有安装后台、替换应用、发布官网或更新项。安装版仍为构建 4。以下为原生组件和隔离驱动验收，不是正式产品发布验收。

## 实现与约束

- `BlockJournalBinding` 增加可选 `authorityEpoch`。旧格式绑定没有该字段，只能用于初始兼容批次。
- `BlockJournalAuthority.newBinding` 由可信组件创建事务 UUID，并绑定当前批次。调用者仍须从可信设备访问层取得卷身份；此方法没有实现设备发现，也不允许不可信客户端自行改写过期请求的批次标签。
- 独立认证状态格式升级为 4，保存批次 UUID 和递增的 64 位序号。格式 1/2/3 可按旧批次导入；旧二进制拒绝格式 4，防止忽略过期请求检查。
- `advanceEpoch` 必须满足：记录非空、每条均为正常提交已结束或回滚已完成、序号未耗尽、选定日志目录为空。任何未结束事务、仅提交未核对事务、未回收日志、未知文件或目录锁冲突都阻止切换。
- `BlockJournalStore.withEmptyDirectoryLease` 持有目录独占锁，核对目录路径/身份、空目录及持久刷新，直到新批次凭据完成原子替换后再次核对。
- 新批次 UUID、递增序号及空记录集在同一个认证快照中持久替换。密钥不变；不重置密钥、不删除设备数据、不清除 NTFS dirty。
- 每个业务入口在处理记录前核对批次：活动凭据读取、保存、准入、完成/恢复、历史查询和日志回收都不能接受过期绑定。
- 批次切换期间阻止业务重入。补充测试复现了切换期间新保存请求与清空记录交错的问题，修复后拒绝该请求；被回调吞掉的错误仍使外层操作失败。
- 已落盘但返回失败的情况按不确定结果处理，重新打开核对，不凭调用结果回退到旧批次。

默认上限仍是每批次 256 条；容量为 2 的专项使用相同机制。系统可以在安全空闲点复用容量，但有未结束事务或目录未知内容时仍会停止准入，不宣称无限资源或任意活动挂载都能清理。

## 切换中断

完整临时切换状态遗留时，显式恢复入口认证旧/新快照，要求旧记录全部结束、新记录集为空、新序号恰好增加 1、新 UUID 不同；再在空日志目录锁内完成原子替换。跳号、旧序号重放、缺失批次标识、旧格式夹带新批次、保留不匹配记录或遗忘活动事务都拒绝。

切换恢复本身再次中断也可重新核对。最后持久化后发生重入错误时，对调用者报告失败，但重新打开仍正确读取已落盘的新批次，不重新接受旧请求。

首轮实现前的占位入口不能真正释放记录，测试因容量耗尽失败，保留于 `red.log`。重入缺陷另有实际失败证据 `red-reentry.log`。修复后专项和完整矩阵按最终源码重新执行；首轮 300 项报告是历史证据，表格列出的是最终源码报告。

## 尚未接通

- 本轮实现显式批次压缩，尚未在正式后台安排自动回收/切换，也未接入 FSKit 持续挂载流程。
- 空目录验证针对调用者选定的可信日志池，不是跨目录日志发现或总空间预算。正式后台须固定并校验池配置，不能把任意空目录当作全局日志已回收。
- 生产独立检查点、真实设备跨连接身份与独占访问仍未完成。当前镜像完整摘要不是 2 TB 卷的生产方案。
- 防重放针对完整保留旧身份的请求；不声称抵御特权攻击者改写整个可信状态/私钥，或不可信调用者被允许自行重新标记请求的错误 IPC 接入。
- 尚未覆盖真实断电、长期真实负载、多卷活动挂载、跨系统兼容及最终安装发行验收。发布阻断保持。
