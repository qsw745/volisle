# 真实写入事务执行器验收

本阶段跑通了**一次性镜像上的完整写入切换**：系统 NTFS 只读挂载 → 正常卸载 → 扩展在持有资源时进行真实 NTFS 预检 → FSKit 可写挂载 → 创建、写入、fsync、读取 → 正常卸载 → 恢复系统 NTFS 只读 → 独立回读一致。此前的实盘脚本读写与后台只读事务不能替代这条应用协调器执行链。

主应用仍没有对普通硬盘开放写入。本次新增执行器严格绑定一个 64 MiB 普通镜像，不能接受物理盘；它运行于开发验收程序，尚未接入常驻 root 服务，也没有跨进程崩溃恢复。不能称为主应用一键写入已完成。

## 改动

- `TransactionalFileSystemAdapter` 增加独占预检与可写激活的事务入口。`MountCoordinator` 将该入口放进既有恢复保护范围；旧适配器仍沿用无副作用预检路径。此前真实预检若在独立 `inspect` 中卸载后失败，会绕过恢复处理。
- `FSKitWriteMountSession` 实现真实系统执行：逐步核对 hdiutil 镜像归属、虚拟设备属性、连接注册表 ID、容量、NTFS 引导摘要和当前挂载来源；拒绝其他驱动所有权。使用固定命令和参数，不执行 shell、强制卸载、修复或清理脏标记。FSKit 扩展的既有只读 NTFS 预检仍是写入前置条件。
- 成功必须经系统挂载表及协调器再次核验；可写状态误报、执行失败或预检拒绝均进入原设备恢复。恢复只正常卸载本会话的挂载路径并删除空挂载目录，再恢复原生只读；未知状态保留设备锁。
- `VolisleMountProbe --write-transaction` 与 `scripts/test-write-transaction.py` 执行真实验收。验收程序必须在编译后重新 Developer ID 签名；脚本现在在连接镜像前检查签名，避免把未进入事务的失败误判为风险拒绝通过。

## 结果

**116 项核心测试、15 个测试组通过。** 新增三个协调器测试覆盖原子预检失败后的只读恢复、恢复未决时保留设备锁及显式重查、实际可写结果核对。保留修复前失败记录 `behavior-red.log`，不是只运行成功分支。

| 实际系统场景 | 结果 | 证据 |
| --- | --- | --- |
| 普通只读扩展收到写入事务 | 无法满足可写挂载核验，恢复原生只读；未写文件 | `.workbench/fskit-readonly-t1mvzhc0/transaction-rejection.json` |
| 绑定镜像的实验写入扩展 | 完整只读→可写→只读流程通过；38 字节中文内容 fsync 后读取相同，原生 NTFS 独立回读相同，恢复后创建被 EROFS 拒绝 | `.workbench/fskit-readonly-u9enzkwe/transaction-result.json` |
| 相同实验绑定、预先设置脏标记的独立镜像 | 扩展实际预检状态 1；系统可写挂载拒绝，恢复原生只读，整份镜像 SHA-256 不变 | `.workbench/fskit-readonly-boz3kc04/transaction-rejection.json` |

所有测试镜像正常分离，没有强制操作或残留盘屿挂载。只读候选场景先于新增整镜像摘要断言执行，因此该行仅证明恢复与未执行文件写入；不将脏卷场景的完整摘要证据推广到它。

### 暴露的真实兼容性限制

首次文件创建使用 `0600` 权限，扩展返回 `ENOTSUP`。原因是既有 `AttributeUpdate` 只接受普通文件 `0644`、目录 `0755` 等固定权限，不支持任意 POSIX 权限映射。失败后恢复只读，镜像摘要未变；随后使用普通创建模式 `0666`、当前 umask 下得到 `0644` 完成事务验收。

本阶段没有假装接受 `0600` 再返回更宽权限，也没有宣称该问题已修复。应用以私有权限创建文件的兼容性仍是正式开放写入前的明确缺口。

### 签名诊断

新编译的开发验收程序最初为临时签名，FSClient 无法发现安装扩展，事务未启动。使用项目 Developer ID 补签后正常发现。早期 `readonly-rejection.log` 的脚本判定过宽，不能作为真实切换验收；已收紧为必须观察到挂载核验失败及恢复状态，合格结果为 `readonly-rejection-signed.log`。

## 下一步接入点

当前缺口已缩小到：将镜像实测的事务执行接入经过认证的常驻后台，加入可写挂载的持久归属和显式关闭/恢复状态，并由主应用真实适配器调用。已有后台的 `finished` 表示只读检查及恢复结束，不能用它表示一个仍保持可写挂载的会话；客户端退出或后台重启时必须还能识别该挂载归属。

这部分接通后，再在已备份 qsw 上验收主应用发起的写入切换。跨进程故障、上述权限模式兼容性、Windows 双向读写、热插拔/睡眠和完整分发验收仍未完成。
