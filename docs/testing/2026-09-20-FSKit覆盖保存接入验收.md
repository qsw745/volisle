# FSKit 覆盖保存接入验收（2026-09-20）

本轮把恢复记录接入了真实 FSKit 的直接覆盖与最终回收回调。仅放行明确绑定的一次性 64 MiB 镜像；普通安装包及真实 2 TB qsw 盘仍只读。没有公开发布，也不代表完整 NTFS 产品已完成。

## 实现

- 新增 `--experimental-replacement`，必须同时指定 `--write-fixture`。构建记录、签名检查分别核对该开关；普通实验写入也不会自动启用覆盖。
- 直接覆盖仅支持同目录、两个不同的普通文件，指纹各不超过 8 MiB，最多同时保留 16 个事务。C 层继续限制 64 MiB 镜像及受支持的文件形态。
- 恢复记录保存在扩展沙盒自己的 Application Support 私有目录。先持久化意图，再保留旧文件、发布新名称；按不可变文件引用区分新旧对象。
- 活跃事务的备份名称不参与正常目录枚举/查找；相关名称和祖先路径的变更被限制。关联文件的数据写入、截断和时间属性更新经过记录、同步与指纹复核；扩展属性变更暂时拒绝。
- 旧对象只在 `tryReclaim` 真正执行最终回收时获准清理；清理前两次检查路径引用与最新内容指纹。失败会终止写会话，未解决的事务使关闭保持失败/脏卷状态。
- 新进程只读检查恢复记录，不恢复删除权限，不执行 NTFS 修复。恢复记录保留用于诊断；还没有归档清理和用户恢复界面。
- `tryReclaim` 在本机 SDK 标记为 macOS 27.0 API，因此直接覆盖实验在较旧系统明确返回不支持。普通候选仍以 26.4 为编译目标；不能把本轮实测外推到 macOS 26.4。

## 实测与证据

1. 新增 `scripts/test-fskit-replacement.py`。先在未开放覆盖的候选复现关闭目标文件时 `ENOTSUP`，记录保留于 `.workbench/fskit-readonly-9oeodsna/replacement-result.json`。目标文件仍打开时会由 FSKit 的打开文件删除仿真处理，原实现已能成功，不能将这个结果误认成原生直接覆盖已实现。
2. 最终自动验收镜像 `.workbench/fskit-readonly-tpjvbdv0`：8 项检查通过，包括直接覆盖、跨目录和超过上限时保留源/目标、旧句柄读写隔离、新文件写入与截断、卸载后独立读取及只读重挂、备份清理、另一进程重新校验沙盒恢复记录。22 个 MFT 记录、672 个占用簇的重叠/位图检查通过。
3. 全量系统回归镜像 `.workbench/fskit-readonly-l0d_orpj`：19 项、100 份文件独立哈希通过；123 个 MFT 记录、1281 个占用簇检查通过。本候选已开放指定镜像的覆盖，所以该项断言改为覆盖后的新内容正确；未开启覆盖开关时仍断言拒绝且两文件不变。
4. Finder 镜像 `.workbench/fskit-readonly-r484kgxl`：通过真实“拷贝 → 替换”，快速查看显示“Finder 新版本内容”；正常卸载、只读重挂及文件内容检查通过，26 个 MFT 记录、672 个占用簇检查通过。系统日志仅记录 1 次直接覆盖事务，来自脚本的关闭文件覆盖；Finder 拷贝替换没有额外触发该事务。原测试误把 UI 替换也计为一次直接覆盖，导致最后日志计数断言失败；原失败结果保留，独立复核记录在 `fskit-replacement-finder-result.json`，脚本已按实际发布次数核验，并在新镜像重新跑通。
5. 重新执行原生恢复记录单元、终止写会话检查和普通镜像 32 个故障/退出场景，全部通过。这是普通文件镜像故障测试，不能冒充 FSKit 进程中断或真实断电测试。
6. `VolisleCore` 41 项、对象身份测试、构建记录、签名描述文件与镜像输入门禁测试通过。最终默认只读应用及扩展本地构建、签名并恢复安装，详情见 `fskit-overwrite-installation.json`。

## 写入怎样开放

用户已经完成系统扩展启用，不需要再找额外的 macOS 开关。当前限制来自产品代码及验收状态。

- 现在：开发脚本仅允许指定小镜像读写，应用对真实盘的写入入口继续关闭。
- 下个门槛：FSKit 路径的中断/写失败、Windows 回读与检查、跨目录/大文件/真实设备刷新语义、系统版本兼容性；特别是 macOS 26.4 的最终回收策略尚未放行。
- 达标后：在应用中提供明确的“启用读写”操作，先对可丢弃介质完成真实设备验证，再测试用户授权盘中的新建测试目录。不会通过一个设置项直接放开所有 NTFS 设备。
- 正式交付仍需签名公证、安装/卸载/更新验收、完整用户恢复流程及发布门禁。官网免费开源与商店收费的路线不变，商店分发可行性仍须单独核验。

## 本轮未覆盖

Windows/chkdsk、实际 USB 断电或拔插、撕裂扇区、整个 FSKit 进程崩溃、休眠恢复、超过 8 MiB 的直接覆盖、跨目录直接覆盖、全量 ADS/ACL 元数据恢复、16 位 MFT 序列回绕。实现仍是保留副本并受控清理，不能描述为崩溃原子替换或零风险写入。

本轮未操作 qsw 上任何已有文件，未卸载、修复或可写重挂真实盘。
