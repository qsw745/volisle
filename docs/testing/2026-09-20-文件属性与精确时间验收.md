# 文件属性与精确时间验收

本轮在已通过的固定缓存块版本上补齐属性处理：修改属性和新建文件都先验证整个请求，再执行受支持的字段，逐项向 FSKit 回报实际成功的属性。时间保留 NTFS 的 100 ns 精度。两份一次性镜像的系统测试通过，Finder 复制兼容性通过；真实盘写入和覆盖保存仍未开放。

## 修改及边界

- 新增 `AttributeUpdate`，支持文件长度、访问/修改/创建时间，以及当前合成类型、权限、所有者、零标志的无变化请求。目录截断、不支持字段、非法日期和溢出在修改前拒绝，避免先截断后才发现请求无效。
- `consumedAttributes` 只标记完成的字段：截断失败不标记长度；截断完成、时间写入失败时只标记已完成的长度。它不是跨字段事务或自动回滚承诺。
- 新建时不再忽略初始属性。验证先于节点创建；后续属性 I/O 失败时仅尝试清理本次新建节点，若底层会话已因 I/O 错误锁定，清理可能失败并留下节点，不能报告成功。
- 当前仍是固定合成 POSIX 权限，显式向系统声明不支持持久设置权限。不支持的 `0600` 文件创建返回 `ENOTSUP` 且不会留下被错误创建为 `0644` 的文件。不能宣称完整 Unix 权限兼容。
- C 桥接增加 `nk_set_times_precise`；空指针表示该字段不变，不再用负时间代表所有未设置字段。时间范围与纳秒字段先全部校验；计算采用宽整数，读取负时间时规范化小数部分。旧秒级接口保留。
- 本机 SDK 的两个能力布尔字段即使在空请求中也报告有效；它们是派生输出，保持未消费，不据此误拒绝所有请求。其余已知不支持的实际属性请求仍拒绝。

| --- | --- |
| 核心包 | 41 项测试通过 |

| 精确时间桥接 | 100 ns 舍入、1970 年以前时间、非法请求零写入、只读重开与拒绝修改、独立 MFT 数值检查、时间写入 I/O 故障锁定会话，6 项检查通过 |
| 原生属性请求 | 成功和部分失败的消费位、混合请求预校验、非法时间、目录截断和权限保护通过 |

| Finder 镜像 | 19 项系统检查通过，99 份文件独立回读；122 条 MFT 记录、1,308 个占用簇未发现所检查的分配问题 |

新增接口和属性消费测试均先观察缺失行为导致的失败，再实现并验证。精确时间独立校验由上游 `ntfscat` 导出 `$MFT`，读取 `$STANDARD_INFORMATION` 原始时间数值，不依赖本桥接的时间解码作为唯一依据。

两轮系统测试都完成 64 次混合分配/删除、部分写入和截断、扩展属性、权限拒绝、正常卸载、独立哈希、只读重挂和分配位图检查。FSKit 修改时间请求 `1700000000987654321 ns` 在重挂后为 `1700000000987654300 ns`，符合 100 ns 向下舍入。

Finder 新建中文目录并复制预置中文文件，GUI 实际显示文件；内容哈希和纳秒修改时间一致。创建时间用 Python `stat.st_birthtime` 浮点秒比较相等，**这项 GUI 样本本身不是创建时间的纳秒精度证明**；创建时间精度另由桥接及独立 MFT 测试覆盖。

结果汇总：`fskit-attributes-result.json`。保留镜像：`.workbench/fskit-readonly-f9in_qrm`、`.workbench/fskit-readonly-sf25q8h3`；详细结果在各目录 `write-result.json`。前者为程序测试，后者增加 Finder GUI，不能混为一次执行。

## 覆盖保存结论与下一步

当前桥接普通改名通过“新名称硬链接 → 删除旧名称”实现。核对上游现有覆盖逻辑后，确认还需要旧目标备份、删除、链接、清理等多个元数据步骤；直接接入不能证明进程终止或断电情况下的原子性。因此本轮没有开放替换改名，系统测试确认拒绝后源文件和目标文件都保留。接下来需要先建立各步骤故障与恢复测试，再实现有明确恢复约束的替换方案。

仍未验证：Windows 回读与 `chkdsk`、真实硬盘持久化、断电/拔盘、完整 Finder 特性、持久 POSIX 权限、所有创建属性组合及公开发行。64 MiB 镜像上的 4 MiB 文件不是大文件验收；分配检查不是完整文件系统检查。

测试结束恢复默认只读安装，具体状态见 `fskit-attributes-installation.json` 和签名账户记录。用户 2 TB `qsw` 保持只读，本轮没有在该盘创建或改动文件。UI 保持现状，没有加入实验写入开关。
