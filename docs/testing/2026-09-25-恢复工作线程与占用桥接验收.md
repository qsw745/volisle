# 恢复工作线程与占用桥接验收

日期：2026-09-25。

## 本轮实现

新增 `RecoveryClaimWorker` 和 `RecoveryWorkerCheckpoint`。同步恢复操作在独立 Dispatch 工作队列执行；需要核对磁盘占用时，将校验发回主执行器，工作线程等待结果。主执行器不等待信号量，能继续处理 Disk Arbitration 的挂载、推出和占用转让回调。

`NativeRecoveryDiskClaim.withPhysicalWorker` 将后台工作的整个生命周期包含在原生占用作用域中，返回或抛错前等待后台退出。取消只撤销后续校验，不提前释放仍可能有系统调用在运行的磁盘占用。工作线程身份固定，跨线程使用、退出后使用及校验失败均拒绝；不使用 `@unchecked Sendable` 绕过隔离。

`checkpoint.deviceSession` 直接构建现有 `BlockJournalDeviceSession`：每次读、写、同步的前后观察都包含原生占用校验，传输层继续负责从已持有句柄生成设备身份、挂载和可写状态。任何底层会话失败都会使整段后台工作保持失败；上层捕获错误也不能返回成功。日志认证、设备打开与身份授权不由这个通用桥接接口代替。

## 验证结果

新增 9 个工作线程测试入口，覆盖主执行器响应、取消等待退出、取消前不执行、校验失败后不可恢复、跨线程及作用域外拒绝、操作异常退出、真实文件读写取消，以及底层错误被捕获后仍拒绝成功。

真实文件测试仅使用新建的 8192 字节临时普通文件。工作线程持有文件描述符，读取旧数据并实际写入一个 512 字节块，在写入回调返回前取消：返回错误、下一次同步未执行、停止写入回调只执行一次、描述符退出前关闭；写过的字节确实保留，其余范围未变。这证明取消不能被当作“没有发生写入”，不是 NTFS 恢复或落盘持久性验收。

真实只读 NTFS 镜像新增验证：后台工作等待时，挂载和推出请求仍被拒绝；取消后、工作尚未退出时，独立系统会话仍无法抢占；工作退出后预约数量恢复且下一次后台作用域可用。原有占用生命周期、超时及迟到回调保护同时回归通过。

## 未完成边界

- 原始设备描述符的生产打开、持有和复核尚未接通；本轮实际数据读写只发生在新建普通文件。真实 DA 镜像测试没有读写原始设备内容。
- 工作线程等待不等于可中断系统调用。系统服务或原始 I/O 永久卡住时仍保留占用，尚未做进程隔离和故障验收。
- 原生占用是 Disk Arbitration 协调，不能阻止绕过该机制的特权原始设备写入；校验与 I/O 之间仍存在窗口。
- 生产检查点、跨重连稳定身份、经过认证的后台恢复协议和 FSKit 持续挂载日志接入未完成。
- 实际 USB 双层占用、热拔插、休眠、多盘、长期负载和支持系统矩阵仍需验收。
- 本轮未接入正式恢复流程，未替换已安装应用、操作 qsw、修改权限、部署网站或发布更新。原有 NTFS 元数据镜像写入中断问题的发布门禁仍阻断。
