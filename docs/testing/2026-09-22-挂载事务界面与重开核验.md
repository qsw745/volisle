# 挂载事务界面与重开核验

后台只读事务已接入主应用。“更多 → 检查只读挂载…”先说明临时卸载及只读恢复，再由用户启动。界面共用一个事务协调器；等待、错误和恢复入口集中在底部，不增加新的状态面板。写入按钮仍未开放。

## 实现

- `MountCycleClient` 在提交前持久保存操作 ID 与精确设备身份。主窗口与菜单栏共用操作屏障；请求超时、响应丢失、状态不明时不能误判为操作未发生，也不能发起新的磁盘操作。
- 应用重开时只查询已保存 ID，不重新提交开始请求。后台完成记录还须经过当前启动会话、设备连接和实际挂载状态核验，才清除本地待办及屏障。只读、未挂载、原设备断开分别显示结果。
- 后台明确拒绝开始请求后，重新核对最近事务；这次核对若失败，继续阻止新操作。后台要求恢复时，仅能恢复其原操作 ID。
- `FileMountCycleIntentStore` 保存用户侧待办，使用原子替换、文件和目录同步；读取拒绝符号链接、错误所有者、硬链接、非普通文件及超限记录。它不授予磁盘操作权限；实际恢复依据仍是后台自己的记录。
- 全局待核验状态不再同时触发每个卷的恢复按钮。底部只保留一个“重新核验”或“恢复只读”，避免重复入口。

## 验收结果

**113 项核心测试、14 个测试组通过；完整应用、扩展和后台组件本机构建、Developer ID 签名及安装通过。** 新增 12 项客户端测试覆盖完成前实际核验、丢失响应、重开只查询、恢复状态不符、权限拒绝、错误操作 ID、拒绝后查询失败、连接变化、持久文件、断开设备、损坏记录及单一恢复入口的状态边界。测试替换操作系统和通信边界，使用实际协调器、待办存储与操作屏障。

实际 UI 与已注册后台验证：

1. 完全磁盘访问关闭时，从新菜单确认开始检查。后台于卸载前拒绝，界面显示权限错误；本地待办清除，Finder/推出重新可用，qsw 挂载和原后台完成记录不变。
2. 退出应用后，受控写入一个引用**此前真实已完成后台操作**的本地待办，再重开应用。应用通过真实 XPC 状态查询及当前设备/挂载核验显示已恢复只读，并自动清除待办。此项是重开核验测试，不是新一次物理盘挂载事务，也不是进行中的实际崩溃测试。
3. 使用另一条受控的、后台未确认的本地待办，验证重开后阻止 Finder、推出和刷新；“重新核验”保持待核验，不重复启动操作。修正重复入口后，在最终安装候选重新实测只有一个按钮。退出后核对测试标记摘要及后台记录未变，仅清理该受控测试标记。
4. 最终正常启动，qsw 显示只读，Finder/推出可用，写入按钮禁用；无待办残留，无盘屿挂载。系统设置实际显示 Volisle Test 完全磁盘访问关闭，后台为 connected。

本阶段没有执行新的物理盘卸载、挂载或写文件。上一阶段 qsw 完整只读事务和 19 文件摘要验证见[后台只读挂载事务接入与实盘验收](2026-09-22-后台只读挂载事务接入与实盘验收.md)，不计为本阶段重新执行。

## 仍未完成

主应用仍使用 `ReadOnlyFSKitEngine`。完整 NTFS 风险预检、FSKit 写入挂载、长期可写挂载归属与异常恢复尚未接通。不能通过打开按钮或复用本次只读事务宣称读写产品完成。

写入接入需保证预检、卸载、挂载和失败恢复组成完整后台事务。现有协调器的 `inspect` 位于写入挂载恢复范围之外，不能简单在此处卸载真实磁盘再返回错误。普通扩展的默认只读策略、实验写入绑定及风险拒绝边界仍须保留。

本地保存但后台始终未确认的请求目前保守保持阻塞，尚无安全的终止/遗忘协议；不能自动丢弃后重新提交。跨系统启动的待恢复记录、多用户冲突、操作中实际崩溃、热插拔、睡眠、压力测试，以及 Windows 双向读写和正式分发验收仍待完成。
