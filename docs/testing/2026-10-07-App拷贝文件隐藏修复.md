# App 拷贝完成但 Finder 看不到文件：隐藏属性修复

核对日期：2026-10-07。用户截图显示向 qsw 拷贝 1 个项目，已拷完 59.7 MB，处于约一分钟的写入确认期。

## 结论与本次文件处理

文件已经写到真实 NTFS 挂载目录，大小为 **59,683,652 字节**，并非尚未改成正式文件名。正式文件的 BSD flags 为 `0x8000`（`UF_HIDDEN`），Finder 默认将其隐藏。写入确认期不会再改名或纠正该属性，等待确认结束不能解决此问题。

本次仅对这一个视频执行 `chflags nohidden`，读回 flags 为 `0x0`，大小不变，修改前后完整 SHA-256 均为：

```text
640955583a6506ba41a6de083817d91d20ba3ac020d6a7a88186870508ee27d8
```

首轮通过 `open -R` 请求 Finder 定位该文件；首轮没有以 Finder 画面目视作为验收证据。后续用户再次拷贝后，本轮已实际读回 Finder 的 qsw 窗口，两次视频和两份验证文件均显示，详见下方主机安装验收。未批量修改磁盘其他文件或系统隐藏目录。

首轮实盘证据：`.workbench/copy-visibility-20261007/user-file-repair.json`。升级前 live 会话为 `writeMounted`，实际挂载在 `/private/var/run/volisle-write-mounts/721e6c7a-80eb-48bc-b850-f84e7c619473`；没有 `top.qisw.volisle.write-state=stopped` 标记。此会话在后续主机升级前已正常结束。此前的硬件读错记录不能代替本次实时状态。

## 根因与修复范围

1. `ResumableCopier` 先写入点名前缀的 `.volisle-part` 临时文件。
2. NTFS create 路径启用 `HideDotFiles`，为临时文件设置 NTFS `HIDDEN`。
3. 完成后 rename 保留 NTFS 属性；原先的 `finishMetadata` 只复制扩展属性与时间，没有清除临时文件的隐藏属性。
4. FSKit 扩展将 NTFS `HIDDEN` 映射为 `UF_HIDDEN`，所以正式文件仍被 Finder 隐藏。

修复位于 `packages/VolisleCore/Sources/VolisleCore/ResumableCopy.swift`：发布前根据源文件属性及最终文件名，只调整 `UF_HIDDEN`。普通文件解除误继承的隐藏属性，主动隐藏的源及点名前缀的正式文件继续隐藏；保留其他 flags。设置后读回核验，失败或未实际生效时不发布文件、不报告拷贝完成。

同一规则覆盖新复制、续传、完整文件复查和符号链接。链接通过 `O_SYMLINK` 描述符操作自身，不修改所指文件。未修改通用 NTFS rename 逻辑，避免改变 Windows 用户主动设定的隐藏属性。
