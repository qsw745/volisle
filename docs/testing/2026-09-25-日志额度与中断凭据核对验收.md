# 日志额度与中断凭据核对验收

日期：2026-09-25。本轮为 `BlockJournalStore` 增加目录额度准入与显式中断核对。25 项专项、149 项真实 NTFS 引擎隔离检查通过；原存储 46 项、事务协调 40 项、可信凭据 43 项、核心包 179 项回归通过。未安装到运行中的后台或 FSKit，发布阻断维持。

## 完整日志领先可信凭据的核对

新入口 `reconcile` 只在外部已持有设备租约的恢复会话使用，不替代普通 `inspect`。普通检查仍要求日志与最新可信凭据完全相等，不自动推进凭据。

核对会认证全部完整记录，并确认可信凭据匹配日志中的精确前缀。只允许相等，或领先 **一条** 记录；这个范围来自事务协调器的“日志持久 → 凭据持久 → 设备写入”顺序。缺少初始可信凭据、前缀不同、领先两条、内容篡改或不完整尾帧都拒绝。当前入口使用默认 64 MiB / 4096 条读取上限。

领先一条时，先刷新现有日志文件，确保完整记录持久，再在保持日志目录排他锁期间调用独立可信存储做比较并更新。只有回执精确匹配新凭据、文件仍与打开时一致，才返回快照。设备字节与日志内容均不修改。更新错误可能发生在凭据已经持久以后；不能直接重试旧请求，须重新读取可信状态。本轮验证了回复丢失后使用新可信状态核对，不重复推进。

这依赖受信任的写者遵守上述顺序，不能用于任意第三方日志。若尾记录是提交，它仍只是该事务已按协议提交，不是卷已 clean 或可以删除日志的证明。设备租约仍由调用方负责，生产端尚未接通；测试驱动持有隔离镜像排他锁。

原有检查同时补强：读取前后、凭据更新前后检查文件名称对应 inode、长度、所有者、权限、链接数和修改时间。回调期间改名或改内容会拒绝成功返回。

## 同一日志目录的额度准入

创建日志前，在目录排他锁下枚举现有日志，检查规范 UUID 文件名、私有普通文件、单链接及有限长度。未知文件、目录、软/硬链接或权限异常都会拒绝；准入检查只统计和检查文件属性，不宣称现有日志内容已认证。

默认目录额度为 **1 GiB、256 个日志文件**。接受新事务前要求剩余额度能容纳该事务的全部单日志预算，默认 64 MiB；持锁期间该组件不会有第二个协作写者竞争额度。超过限制会在创建新文件前失败，已有日志原样保留。额度参数有上限，枚举和累加有界。

这是逻辑额度，不是物理磁盘预分配，不保证不会遇到系统盘空间不足。它只覆盖同一目录，多目录之间不共享预算；正式后台必须统一日志池或增加跨池预算管理。当前还没有部署这样的后台日志池。

没有新增自动删除、按时间淘汰或凭据退役。持续挂载的提交日志可能仍是后续恢复的依赖，单凭“已提交”不能安全回收。达到额度后宁可拒绝新写入；长期运行需要补齐设备静止、最终状态核验、依赖关系和可恢复的退役协议。
