## 本轮修复的验收工具问题

这次实际测试暴露了三个工具问题：root 文件属主与扩展普通用户不一致、macOS Python 不提供 `os.setxattr`、拆成多个 sudo 终端任务导致多次密码提示。系统 CoreDeviceService 对 diskutil 的卸载拒绝是另一项环境问题，最终通过不带强制参数的标准 umount 正常卸载。

新增 `scripts/run-physical-acceptance.py` 将下一轮磁盘操作合并成一个管理员任务：

1. 普通用户阶段核对新绑定、签名候选及安装摘要，将任务放在内部临时目录；此步骤不提权、不挂载。
2. 打开生成的 `.command` 后，由 sudo 获取一次授权；执行前校验固定的脚本和输入摘要。
3. 核对当前设备、NTFS 引导摘要、安装副本和有效期，正常卸载系统只读卷。
4. 绑定范围可写挂载；以登录用户身份创建专用目录、检查越界拒绝、执行文件操作，使用系统 xattr。
5. 正常卸载、盘屿只读重挂校验、再次卸载、系统 NTFS 只读回读。异常路径尝试正常恢复，并单独记录恢复失败。

没有格式化、修复、强制卸载、通用 root 命令服务或系统服务终止步骤。任务拒绝已存在的测试目录与重复执行；绑定过期、设备变化或签名副本不一致时停止。普通只读应用的最终恢复仍由非管理员安装核验步骤完成，不需要额外 sudo。

下一轮准备方式（需先生成并安装新的匹配测试候选，不能重用旧绑定）：

```sh
python3 scripts/run-physical-acceptance.py \
  --prepare .workbench/本轮记录/binding.json \
  --candidate-dir apps/macos/build/本轮签名候选
```

该命令只生成任务路径，不自动打开终端。系统是否提示密码取决于 sudo 当前授权状态；流程自身仅调用一次 sudo，不修改密码策略或系统权限。
