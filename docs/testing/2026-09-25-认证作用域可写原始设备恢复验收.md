# 认证作用域可写原始设备恢复验收

日期：2026-09-25。源码和证据目录：`.workbench/native-write-20260925/`。

## 本次结果

恢复链路首次接入真实的可写 `/dev/rdisk…` 字符设备节点，通过新建 64 MiB NTFS 镜像完成认证日志恢复、设备同步、逐块回读和整镜像摘要验证。不是普通文件写入替代设备写入，也不是内存设备模拟。

仍是内部恢复组件。本次未接入安装版的后台/FSKit 持续挂载流程，不能据此开放正式下载或声明整个产品完成。

## 实现与约束

`BlockJournalDeviceRecovery` 仅在权威状态、日志与独立基线通过认证之后创建 `BlockJournalRecoveryPermit`，交给设备工厂。许可构造器仅在该文件可用，不可序列化、不可跨线程传递；退出恢复回调后立即失效，旧对象无法重新打开设备或授权后续写入。设备仍保持到完成回执持久化之后关闭。

`NativeRecoveryDiskClaim.withPhysicalRecoveryConnection` 继续沿用外接 USB 分区、当前启动代号、IOMedia 身份、整盘及分区未挂载的准入策略，持有 Disk Arbitration 占用直到后台恢复线程退出。内部目标只能由原生占用层创建；写入传输层及文件描述符不向调用方暴露。

`NativeRecoveryConnection.openDevice` 校验认证绑定、容量、扇区兼容性及独立基线，再以 `O_RDWR | O_NOFOLLOW | O_CLOEXEC` 打开原始设备。每次设备观察重新核对字符设备及路径身份、打开模式、可写性、实际几何、NTFS 引导摘要，并通过工作线程检查点复核原生占用。任何读写错误均停止当前会话，不改为直接写入或强制清除 dirty。

写入按日志完整块执行，短写不重试为成功。同步使用 `fsync` 后接 `DKIOCSYNCHRONIZECACHE`，任何失败均拒绝发布恢复成功。逻辑读取允许非扇区对齐的小范围，通过有界的对齐范围、每次最多 1 MiB 的精确原始读取再截取；零长度、设备尾端和溢出范围均单独校验。

连接身份包含当前系统启动 UUID 与 IOMedia registry ID。同一启动和同一媒体实例可在后续恢复占用中核对，重新插拔或重启会被拒绝。这不是持久卷身份策略；跨连接恢复仍待实现。Disk Arbitration 占用也不等于阻止其他特权进程直接写盘的内核级排他机制。

## 实盘节点测试

运行 `python3 scripts/test-native-recovery-write.py`，只创建 `.workbench/native-write-*` 下的独立 64 MiB 文件；挂载前记录全镜像及引导摘要，在确定为全零的单个 4096 字节测试块植入中断状态。测试自行构造相应认证日志，不宣称这些日志来自正常生产写入会话。

随后将镜像连接为未挂载、可写的系统设备节点，通过原生恢复入口测试三个场景。最终报告为 `.workbench/native-write-20260925/writable-runtime-result.json`：

| 场景 | 证据 | 结果 |
|---|---|---|
| 错误引导指纹 | `.workbench/native-write-cxbd26sl/` | 在设备工厂拒绝，验证器未执行，捕获预期身份错误；全镜像未变 |
| 独立验证拒绝 | `.workbench/native-write-q_lr7u0q/` | 已打开真实设备，虚拟恢复视图校验完成后主动拒绝；没有写回，镜像未变 |
| 正常恢复 | `.workbench/native-write-9yxk4y6x/` | 恢复 1 块，设备同步、逐块回读、恢复前后两次视图验证通过，持久回执匹配 |

正常恢复完成并正常断开设备后，全镜像 SHA-256 为 `5dda7ead15c7c2fdc2cc634268055a8dd28da01e244d750a4e41342487721345`，与事先独立保存的基线一致。还覆盖跨扇区读取、非对齐 1 MiB 读取、末字节、零长度尾端、许可过期拒绝及原始设备句柄无泄漏。三个场景均正常断开，仅删除成功的新建测试镜像。

本测试使用真实 NTFS 格式的镜像和原始设备传输，但故障块是人工植入的测试块；它不等于已经在可写原始设备上完成 FSKit 元数据中断恢复。真实 NTFS 引擎的完整元数据故障矩阵另行通过下述普通隔离镜像回归。

## 发现与修复

首轮正常恢复在任何设备写入前被错误拒绝，失败镜像已保留。分阶段证据定位到：权威凭据初始批次合法使用空 epoch，新准入却错误要求 epoch 非空。新增失败测试重现后，删除这个错误条件，继续由认证权威核对 epoch 与当前状态是否完全一致；没有绕开日志认证。

第一版负向测试只要求抛错，可能误把上述准入错误记作预期失败。最终测试增加具体错误类型、到达阶段和验证器次数断言；上表只列修正后重新执行的结果。初轮失败或弱断言结果不作为验收通过证据。
