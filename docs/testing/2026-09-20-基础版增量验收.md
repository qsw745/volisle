# 免费基础版增量验收

日期：2026-09-20。

路线更新：用户随后改为免费开源优先，后续评估 Mac App Store 收费。下文商业 SDK 状态为当时验收背景，当前已暂停询价，不再作为研发前置条件。

## 已实现

- 引擎状态使用实际注入的 `FileSystemAdapter.capability()`，设置页可重新检查，卷详情显示产品引擎状态；当前注入 `UnavailableEngine`，明确不可用，不借用已安装第三方驱动。
- 诊断导出前显示固定快照，用户可选择文本或 JSON；仅保留系统版本、卷数量、白名单文件系统分类和聚合挂载状态等字段，无自动上传。
- 文件系统分类以白名单输出，未知类型归为 `other`；不输出任意名称、设备信息、身份 UUID、路径、自由文本风险/错误或引擎授权秘密。
- 修正挂载协调顺序：身份/保护范围核对 → 已知风险拦截 → 引擎风险检查 → 身份与新风险再核对 → 挂载前取消检查。发现服务的未知风险允许进入检查，但引擎返回未知或风险仍拒绝挂载。
- GPL 实验与商业主线继续分离，未引入供应商代码、驱动或费用。

## 验证

`swift test --package-path packages/VolisleCore`：19 项 Swift Testing 测试通过（含一项 3 组风险参数用例）。测试使用明确标注的替身，不访问真实卷，不代表真实 SDK 挂载成功。

新用例覆盖发现状态未知后实际调用引擎检查、引擎未知/危险拒写、新风险覆盖旧安全结果、保护卷不触发引擎检查、非空敏感样本的诊断脱敏、引擎真实不可用状态。原有身份替换、设备互斥、缺失引擎和错误恢复测试继续通过。

`zsh scripts/build-macos.sh`：Release 构建通过；开发包 Info.plist 校验通过。

`swift run --package-path apps/macos -c release --skip-build VolisleProbe`：本机只读枚举正常退出，报告 1 个物理设备分组、2 个外接卷（APFS 已挂载可写，MSDOS 未挂载）；同时明确产品引擎与产品 Finder 写入不可用。仅记录聚合信息，未写入这些卷。

## 后续原生界面验收与修复

同日通过原生 UI 自动化操作实际 Release 应用。正式开发包没有配置分发 Bundle ID，自动化无法按应用识别，因此在 `.workbench/ui-qa` 创建隔离副本，仅为测试添加随机 `test.local.volisle.qa.*` 标识和“盘屿界面验收”名称。可执行文件与产品开发包相同；临时标识不是正式分发命名空间，不进入产品构建脚本，不宣称已拥有正式 Bundle ID。

发现并修复三项实际界面问题：

1. 首次打开诊断弹窗空白：将单独的布尔开关与可空报告改为 `sheet(item:)`，由携带报告的单一呈现状态控制弹窗。
2. 应用内 Logo 不显示：不再依赖 SwiftUI 按名称查找独立 PNG，改用 `Bundle.module` 明确定位并通过 `NSImage` 加载；侧栏与诊断弹窗均目视显示正常。
3. 设置窗口未跟随应用深色偏好：为 Settings 场景应用与主窗口相同的颜色方案；实际深色设置窗口已复测。

实际完成的交互：首次打开诊断、关闭和重新打开、系统保存面板导出 JSON、导出文本、取消保存、设置页重新检查引擎、切换深色外观、选择未挂载卷。未挂载卷的 Finder 按钮确认为禁用；产品引擎始终准确显示不可用。

导出文件：`2026-09-20-GUI诊断样本.json`、`2026-09-20-GUI诊断样本.txt`。回读 JSON 核验白名单字段、版本、2 个外接卷与引擎不可用状态，文本与 JSON 的聚合状态一致，不含卷路径。未把界面里的真实卷名或完整设备资料写入验收记录。

最终 Release 构建和 Info.plist 校验通过。此次只修改界面呈现与资源加载，核心模块未变化，前一批 19 项核心测试结果仍为该核心代码的验证依据，未无意义重复执行。GUI 覆盖限定当前机器和所列交互，不等于 NTFS 闭环或完整无障碍验收。
