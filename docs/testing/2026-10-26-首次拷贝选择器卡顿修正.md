# 首次点击“拷贝到这块盘…”卡顿修正

2026-10-26，用户反馈第一次点击出现鼠标转圈，再次点击很快。修正提交 `26c748c`；本机安装 **0.9.10（84）**，未发布。

## 根因与证据

- 对已安装 83 号版点击采样，主线程共 1057 采样点，330 点位于 `CopyPicker.sources → NSOpenPanel.init → NSSavePanel._initBridgeAndStuff → HIRunLoopSemaphore`，正在等待系统文件选择服务连接；此时尚未进入拷贝计划或并发队列。
- 两次工具点击到可访问性快照完成分别为约 4.25 秒、4.26 秒。因此本机工具未复现用户描述的第二次明显加快；能确认的是创建选择器时的等待，不能据此断定所有机器只有第一次慢。
- 独立 AppKit 探针首次初始化约 0.43 秒、后续新建约 0.14 秒；已创建实例的复用取值几乎无耗时。使用正式修正代码的隔离窗口，准备完成后首次点击至异步 begin 调用返回约 29 ms。该数值不等于完整绘制耗时。

## 修改

- 磁盘就绪后，在主线程提前准备一次系统文件选择器，并在来源、目标两步间复用；保持 AppKit 的线程要求。准备期间拷贝入口暂时禁用，完成后恢复。初始化成本仍然存在，并没有放到后台线程或声称冷启动无成本。
- 来源默认本机用户目录，并独立记住本次进程最近确认的源目录，不再继承目标盘的临时挂载路径。
- 使用公开的异步 `beginSheetModal`／`begin`，替代两个同步 `runModal`。按 SDK 文档，在完成回调中先 `orderOut` 再复用，避免关闭动画与下一个面板冲突。
- 选择期间禁重复触发；退出时取消选择任务并关闭可见面板；每次异步选择、核验、计划返回后检查取消和磁盘会话，入队前再次验证卷与根目录。
- 未改拷贝引擎、双任务调度或安全权限。

公开 API 依据：[Apple begin(completionHandler:)](https://developer.apple.com/documentation/appkit/nssavepanel/begin(completionhandler:))，以及本机 SDK `NSSavePanel.h` 关于 sheet completion 可能先于关闭动画、需 `orderOut` 的说明。

- 直接编译正式 `CopyPicker` 的取消回归：已取消 Task 调用来源及目标入口立即返回 nil；`NSApp` 仍为 nil，不创建应用或面板。
- 独立复核发现并修复异步核验后缺少取消检查的问题；复核无剩余确定的阻断问题。
- 全套核心 **532 项／51 套**通过；三语 **749 键／0 问题**；App、扩展、后台均本机 arm64 + x86_64 构建通过。
