# 原生设备占用与生命周期验收

日期：2026-09-25。

## 实现

新增 `NativeRecoveryDiskClaim`，通过 macOS Disk Arbitration 建立有作用域的设备占用。正式入口只接受明确标记为外置 USB 的可写分区，核对本次系统启动标识、媒体注册 ID、容量、物理块大小、整盘及分区的当前身份，并要求同一整盘下没有已挂载卷。旧启动请求在查找设备前被拒绝。

在整个操作作用域中，先申请整盘占用，再按需申请目标分区占用；注册挂载、推出、占用转让和设备消失回调。挂载、推出和转让请求会收到拒绝；设备消失或身份复核失败则使会话失效。操作正常返回、抛错或已取得占用后的任务取消均执行释放与回调注销，退出后的旧对象不能继续验证为有效。

没有用 `DADiskIsClaimed` 的一次查询替代原生仲裁。真实镜像测试发现系统本身可能已占用镜像，当前实现调用 `DADiskClaim`，仅在原持有者和系统同意后进入操作；竞争者再次申请时由已持有会话的拒绝回调保留占用。

C 回调在主队列执行，先复制名称/状态值，再进入主线程隔离域；没有给系统对象添加不安全的并发声明。返回的拒绝对象由调用方接收并释放，依据 [Apple 的回调所有权说明](https://developer.apple.com/documentation/diskarbitration/dadiskclaimreleasecallback)。

测试入口由 `#if DEBUG` 限定，只允许 `.workbench/native-claim-*` 下本用户新建、单链接、恰好 64 MiB、无分区且以只读方式挂接的普通镜像；逐次复核文件身份与 `hdiutil` 的镜像映射。正式入口不接受镜像路径或测试开关，后台 XPC 没有暴露此测试入口。

## 真实系统验收

使用新建 NTFS 镜像，经 `hdiutil -readonly -nomount` 实际挂接，再调用原生接口；没有使用模拟 Disk Arbitration 返回值。

最终生命周期测试通过：

- 取得并复核占用；另一会话申请被拒绝，实际占用转让拒绝回调被调用。
- 实际挂载、推出请求被拒绝，对应拒绝回调被调用。
- 正常退出后另一会话能够重新取得占用。
- 操作抛错、取得占用后的任务取消均释放占用；随后可再次取得。
- 退出作用域后保存的旧对象验证失败。
- 所有占用与回调释放后，镜像能够正常只读挂载；已挂载镜像再次申请恢复作用域被拒绝。
- 正常卸载、分离成功，镜像的完整 SHA-256 与测试前相同。

最终报告：`.workbench/native-claim-adkmr2kl/result.json`；运行日志在同目录的 `test.log`。脚本只在成功后删除自己本次创建的镜像文件，保留报告；先前失败镜像均正常分离、内容未变并保留证据，没有强制分离或修复。

核心包回归报告为 **199 个测试入口、23 组**，其中镜像生命周期入口在普通回归中按条件跳过（其余 198 个执行通过）；该入口已在上述实际挂接镜像中单独运行通过。不能把条件跳过算作另一笔设备验收。命名、设备族边界、物理介质策略、非法目标和旧启动请求的检查也通过。

发布配置本地构建通过。额外以 `-c release -Xswiftc -enable-testing` 仅开放内部符号可见性，执行两个只做类型检查、不运行的探针：正式物理入口可引用；测试镜像入口明确报 `has no member 'withReadOnlyFixtureClaim'`，证实未进入发布配置模块。探针及 `release-positive.log` / `release-negative.log` 保留在证据目录。这是核心模块验证，没有生成或安装新的正式 App 发行包。

## 已发现并修正

首次测试缺少实现的失败保留于 `red.log`。接入时先修正系统回调的 `Bool` / `Unmanaged` 类型及 Swift 6 隔离边界；运行脚本的设备容量字段改为现有平台的 `TotalSize`。实际系统测试随后发现“已占用就直接拒绝”会阻止合法仲裁，已修正并验证真实竞争者仍被拒绝。旧启动绑定的失败记录保留于 `boot-red.log`。

最终使用 `runtime-complete.log`、`core-final.log` 和 `release-final.log`；先前失败日志保留，不能用中间版本替代最终结果。源码摘要与下一步见 `.workbench/native-claim-20260925/source-hashes.json`、`handoff.json`。

## 未完成和适用限制

此适配器负责 Disk Arbitration 占用，**没有打开原始设备、执行恢复写入、认证日志或证明文件系统健康**。它不能防止特权软件绕过 Disk Arbitration 直接访问设备，不能据此声称已获得内核级原始设备独占权。

- 物理 USB 分区入口尚未在 qsw 或其他实盘运行；整盘与分区两级占用、多分区拒绝、真实热拔插/睡眠与系统服务异常仍待验证。本轮只读无分区镜像只执行一次整盘占用。
- 系统等待期间的取消在收到原生回调后才处理；尚未实现独立超时和失联系统服务的清理策略。
- 调用方必须保持回调主队列响应，不能在作用域内阻塞主队列进行长时间原始 I/O。恢复工作线程与占用状态的安全桥接尚未实现。
- 跨重启/跨 USB 连接的生产卷身份认证、已持有原始设备描述符的复核、生产检查点及后台/FSKit 恢复接入仍未完成。上一轮共用 I/O 会话尚未接到此原生占用适配器。

本轮仅本地构建与测试，没有修改 qsw、系统权限、已安装 App、官网或公开更新目录。正式发布门禁维持阻断。
