# 后台磁盘访问权限诊断

本轮用户确认开启后台组件后，实际系统服务已运行，主应用成功收到 root 服务状态回复。此前的“等待系统授权”已解除，但这不等于磁盘访问获准。

## 开启完全磁盘访问前的诊断

1. 对 qsw 的错误注册表 ID 请求被实际系统后台服务拒绝。
2. 对正确设备身份的只读请求被系统拒绝，内核记录 `VolisleMountHelper ... deny(1) file-read-data /dev/disk7s1`。前后挂载均为系统 NTFS 只读，没有挂载、卸载、修复或写入操作。
3. 实际系统设置显示“文件与文件夹 → Volisle Test → 可移除的宗卷”已经开启。不存在需要用户重复开启该开关的证据。
4. 给主应用增加主动只读访问入口及用途说明后，实际界面仍得到后台访问拒绝。用途说明或一次访问尝试不能被视为授权成功。
5. 按 Apple 对辅助进程归属的说明，为封装的启动配置增加 `AssociatedBundleIdentifiers = [top.qisw.volisle]`，重新签名、安装、注册后仍无法读取。该归属配置未解决本机的限制。
6. 当前 macOS 实测版本为 **27.2**。上述现象不能直接外推到其他 macOS 版本。

实际服务注销、更新后重新注册、状态连接均已成功，不再要求重复批准后台开关。下文记录用户随后明确授权的临时权限核验及最终恢复状态。

## 产品实现增量

- 新增 `DiskAccessCoordinator`，共享设备操作锁，明确区分触发授权与实际后台读取结果。授权期间连接变化会停止后续访问；收到结果后再次核对原连接，不能把新插入的同名设备当成原目标。
- 主窗口“更多”菜单增加“检查磁盘访问…”，只对当前选中的 NTFS 卷提供入口，不在启动或发现磁盘时自动请求权限。
- GUI 主进程先验证完整签名包和后台服务，通过只读打开尝试触发系统自身的可移动宗卷授权，再通过原有签名 XPC 通道实际复核。前台尝试不读写磁盘内容、不改变设备权限。
- 添加 `NSRemovableVolumesUsageDescription`。不包含私有授权 API、TCC 数据库修改、SIP 修改、sudo 或通用 root 命令接口。

核心测试 **12 组、90 项全部通过**，包括授权弹窗完成但后台仍拒绝、授权期间连接变化、只读结果不授予写入或健康检查资格、设备互斥。完整应用和默认只读扩展本机编译、Developer ID 签名及安装校验通过；主界面和菜单入口已实际操作检查。

## 参考与判断边界

[Apple DTS 对原始设备读取被拒绝的同类说明](https://developer.apple.com/forums/thread/802650)指出，主应用可以触发可移动宗卷许可，辅助进程在适用情形下继承访问。该案例不是本机已验证成功的替代证据。本轮按此路线测试后仍失败，所以继续保留权限拒绝结果。

[Apple 的服务管理示例](https://developer.apple.com/forums/thread/802443)覆盖后台服务注册批准流程。本轮已经通过这一生命周期；不能将磁盘访问错误误报为后台注册未完成。

## 用户授权后的实际核验与最终状态

用户回复“开启”，明确允许临时为 **Volisle Test** 开启完全磁盘访问。用户在系统验证界面完成认证；没有收集密码。系统设置显示开关开启后执行以下检查：

1. qsw 仍被系统 NTFS 只读挂载时，身份检查返回通用失败。新加入的有限诊断日志明确记录 `open(..., O_RDONLY | O_NOFOLLOW | O_CLOEXEC)` 返回 `errno=16`（EBUSY）。不是设备断开，也不是这一阶段的权限拒绝。旧错误映射丢失了这个区别。
2. 在核对 `disk7s1`、IORegistryEntryID `4296011625`、分区大小 `2000396321280` 后，执行正常 `diskutil unmount disk7s1`。不使用 force，不操作其他盘。
3. 原有签名 XPC 通道连接实际 UID 0 系统服务，后台只读读取引导区成功，SHA-256 与既有记录一致：`23d135ee49cb374b1c51f764477159bf514091de84167c3e6867a8736b3bd7c7`。报告明确 `writeAccessAvailable=false`、`fileSystemHealthChecked=false`。
4. 执行 `diskutil mount readOnly disk7s1` 成功恢复 `/Volumes/qsw`，挂载描述与检查前完全一致。既有专用测试目录清单中的 **19 个文件**逐个 SHA-256 检查前后均通过，清单本身也未变化。本轮没有创建、删除、修改磁盘文件，没有修复或格式化。
5. 核验完成后，在系统设置关闭 **Volisle Test** 的临时完全磁盘访问，实际界面已显示关闭。其他应用权限未修改。
6. 最终候选已本地编译、Developer ID 签名、严格签名核验、替换安装并重新注册，系统组件状态为 connected。新服务在关闭完全磁盘访问后再次返回权限拒绝，作为撤销生效的实际证据。

已修复 `EBUSY` 映射为 `.busy`，提示“磁盘正被系统或其他程序使用，暂时无法检查。”，避免误导用户检查连接或反复授予权限。诊断日志只记录操作阶段、errno 和读取长度，不记录文件内容、磁盘标签或路径；短读取不再错误沿用上次系统调用的 errno。新增错误映射回归测试先失败、修复后通过，最终 **12 组、91 项核心测试通过**。

服务重启实验中，在注销后立即注册曾得到一次 `Operation not permitted`；随后查询显示服务确实已注销。完成本地候选更新后重新注册成功，不需要再次批准，也没有采用无限重试。这不等于已验证任意间隔下的服务重启可靠性。
