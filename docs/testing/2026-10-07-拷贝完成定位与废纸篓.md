# 拷贝完成后在访达中选中项目、废纸篓行为验收

核对日期：2026-10-07。主机 macOS 27.2，真实 qsw NTFS USB 分区 disk8s3。用户要求将完成卡片的“好”改成“打开文件”，并询问磁盘内删除是否应该每次提示。

## 实现与交互

- 完成且经过原有写入确认期后，卡片显示“打开文件”，点击调用 `NSWorkspace.activateFileViewerSelecting`，在访达中选中本次实际完成的顶层文件或文件夹。目录只选顶层目录，不把每个内部文件都展开；跳过项目不选中。
- 打开前重新核验当前磁盘身份和任务 `diskKey`，读写状态使用已验证的当前写挂载，恢复只读后使用当前系统挂载，不保存过期会话路径。
- 成功请求定位后关闭完成卡片，延续原“好”的收起行为。失败提示原因并保留记录。另加关闭记录的 `xmark` 按钮，磁盘离线、文件已移走或整批跳过时仍能收起。
- 整批跳过提示“这次拷贝没有可打开的项目。”，实际完成目标均已不在时提示“拷贝的项目已移动或删除，无法在访达中定位。”。

源码：`apps/macos/Sources/Volisle/CopyViews.swift`、`MainView.swift`、`VolisleApp.swift`。未修改普通文件删除流程或核心复制引擎；保留前轮复制文件误继承隐藏属性的修复及 macOS 15 兼容改动。

## 真实 App 和访达验收

为避开前轮界面自动化工具在 `NSOpenPanel` 关闭后持续超时的问题，App 退出时仅加入三份自建小文件任务的初始持久计划，再由真实 App 加载、复制和确认。没有用 `cp` 代替复制引擎，没有人为将任务设置为确认完成；本轮未重新逐个点击源／目标选择器。

| 场景 | 实际结果 |
| --- | --- |
| 单个 65,536 字节文件，正常等待约一分钟确认后点击“打开文件” | 访达选中 `Volisle定位验证-单文件-969ff11c.txt`，状态栏选择 1 项；当前路径为真实写挂载 `31fbd6fd-6c43-49a8-bef2-ad9a4631a47d` |
| 一批文件及文件夹，正常恢复只读后点击“打开文件” | 访达在 `/Volumes/qsw/` 同时选中 `Volisle定位验证-文件-969ff11c.txt` 和 `Volisle定位验证-文件夹-969ff11c`，状态栏选择 2 项 |
| 源在计划后被移走，实际点击“跳过此项”，等待确认 | 点击打开显示“这次拷贝没有可打开的项目。”，记录保留；关闭提示后点击 `xmark`，记录正常收起 |

最后重新通过 App 启用 qsw 读写，恢复用户使用状态；仅将三个自建验证项目移到这块盘的废纸篓并读回内容，没有清空废纸篓。

## 删除是否需要提示

App 当前没有普通文件删除界面；用户在访达中的“移到废纸篓”通过系统文件操作执行。普通移入废纸篓无需每次再确认，文件立即从原目录消失；“立即删除”或清空废纸篓属于永久删除，应保留系统警告（用户可以在访达设置中关闭清空警告，Option 也能绕过单次警告）。

这块盘已实际验证 `FileManager.trashItem`，前轮两个 204,800 字节验证文件仍在 `.Trashes/501`，大小及完整摘要一致。本轮只读核对发现先前两份视频也有匹配名称和大小的废纸篓项目：59,683,652 字节文件沿用原名，4,539,156,898 字节文件因已有旧同名项目改为 `2026-09-20 195603 18.57.36.mp4`。未对它们执行移动、恢复或删除，本轮未重算两份视频完整摘要；不能把旧同名 786,432,000 字节项目当作这份新视频。本轮自建项目同样成功移入废纸篓并读回内容。因此保持访达标准删除交互，无需给每次普通删除额外加确认，也不在文件系统底层删除回调中弹窗。

依据：[苹果“在 Mac 上删除文件和文件夹”](https://support.apple.com/zh-cn/guide/mac-help/mchlp1093/mac)、[Foundation 废纸篓 API](https://developer.apple.com/documentation/foundation/filemanager/trashitem(at:resultingitemurl:))、[AppKit 访达定位 API](https://developer.apple.com/documentation/appkit/nsworkspace/activatefileviewerselecting(_:))。
