# 商店版 Pro 第 0 步：沙盒验证结果

日期：2026-10-15。环境：macOS 27.2，本机（Apple 芯片）。计划见 `docs/architecture/商店版高级功能第一批-实现计划.md`。

测试应用：`scripts/store/probes/power-probe.swift`，用 `scripts/store/probes/build-power-probe.sh <输出目录>` 构建。它是独立的沙盒应用（标识 `top.qisw.volisle.probe.power`，Developer ID 签名，只带 `com.apple.security.app-sandbox`），不带扩展，也不碰商店版。日志子系统 `top.qisw.volisle.probe`，用 `/usr/bin/log show --predicate 'subsystem == "top.qisw.volisle.probe"'` 查看。

磁盘相关的检查用的是已装的 TestFlight 版（1.0 构建 5）和测试盘“希捷 2T”（Seagate Expansion 2 TB，所有者授权随意测试）。

## 结论

| 项目 | 结果 | 对计划的影响 |
|---|---|---|
| 沙盒里创建防睡眠断言 | 通过 | 照计划做 |
| 沙盒里注册“登录时打开” | 通过（未实际注销重登） | 照计划做 |
| 沙盒里收到“即将睡眠”并推迟睡眠 | 通过 | 照计划做“合盖前推出” |
| 商店版的“推出”会发缓存同步命令 | 通过 | “推出后可以拔”的说法成立 |
| 访达会不会在盘上写 `.DS_Store` | 不会写 | 拦截不用做 |
| `._` 文件 | 不会产生 | 不用做 |
| `.Trashes`、`.fseventsd` 在 Windows 里隐藏 | 引擎早就这样做了 | **“不留杂文件”没有新东西可卖，建议移出 Pro** |

## 1. 防睡眠断言

`open -n … --args assert 8`：`IOPMAssertionCreateWithName(PreventUserIdleSystemSleep)` 返回 0；`pmset -g assertions` 里能看到 `pid …(PowerProbe) PreventUserIdleSystemSleep named: "Volisle probe: writing"`；8 秒后释放，返回 0。

## 2. 登录时打开

依次运行 login-status → login-register → login-status → login-unregister → login-status，状态是 3（未找到）→ 1（已启用）→ 1 → 0（未注册）→ 0。注册时没有弹出要用户批准的提示（状态没有变成 2）。测完已注销。没有实际注销再登录，所以“登录后会不会真的打开”还没看到；这个 API 是苹果给商店应用的标准做法，风险很小，正式版用 TestFlight 构建再确认一次。

## 3. 推迟睡眠

测试应用注册 `IORegisterForSystemPower`（沙盒里成功，没有沙盒拒绝记录）。收到“即将睡眠”后，等指定秒数再调 `IOAllowPowerChange`。

- 第一次（推迟 15 秒）：11:19:36.96 收到“即将睡眠”（`NSWorkspace.willSleepNotification` 也在同一毫秒到达），11:19:52.71 放行。系统电源日志写着 `Delays to Sleep notifications: [PowerProbe is slow(15762 ms)]`，说明系统确实在等这个沙盒应用。这次屏幕在 2 秒后就亮了，放行后系统直接取消了睡眠，没有真正睡下去。
- 第二次（推迟 10 秒，所有者不碰键盘）：11:21:33.30 收到“即将睡眠”，11:21:43.78 放行，电源日志同一秒记下 `Entering Sleep state due to 'Software Sleep …'`，并写着 `PowerProbe is slow(10523 ms)`。放行之后系统马上睡下去了。

做法定下来：用 `IORegisterForSystemPower`，在“即将睡眠”里推出磁盘，推完或到上限就放行。系统等待有上限（以往约 30 秒），正式版上限定为 20 秒。`NSWorkspace.willSleepNotification` 只是通知，不能推迟，不用它。

## 4. 推出会发缓存同步命令

11:10:04 在 TestFlight 版里点“推出”（盘当时是可读写挂载），11:19:17 所有者拔线。拔线时内核那行记录（`IOUSBMassStorageDriver … Misc>`）按 Cur 换算：

- 最后一次写入（LWr，0x2A）：11:10:04.98
- 缓存同步（SyC，0x35）：11:10:05.07，在最后一次写入之后 91 毫秒
- 停转（StS，0x1B）：11:10:05.97

和官网版 0.9.4 的结论一样：用盘屿自己的“推出”之后再拔线是安全的。推出后盘在“磁盘工具”里仍然列着，是 USB 固定介质的正常现象。

## 5. Mac 杂文件

在测试盘上建了测试文件夹，用访达（AppleScript）切换图标显示、改排列、改图标大小、挪图标位置、改背景色，等了 10 秒：

- 本地文件夹（对照）：写出了 6148 字节的 `.DS_Store`；
- 测试盘：没有 `.DS_Store`。盘上原有的文件夹里也没有（查了三层）。

写了扩展属性的文件（`xattr -w`），属性直接存在 NTFS 里，没有 `._` 文件；盘上原有文件的 `com.apple.macl` 等属性也是这样存的。

盘上确实会出现的 Mac 文件只有 `.fseventsd`（挂载时系统建的）和 `.Trashes`（在访达里移到废纸篓时建的）。聚焦索引在这个卷上是关闭的（`mdutil -s`：Indexing disabled），不会有 `.Spotlight-V100`。

这几个名字引擎在创建时已经加了 HIDDEN 和 SYSTEM 属性（`packages/VolisleNTFS/bridge/ntfs_bridge.c` 的 `mac_metadata_name`，`.DS_Store`、`._*`、`.Trashes`、`.fseventsd` 等都在内），Windows 资源管理器默认不显示，打开“显示隐藏的项目”也看不到。Mac 上 `ls -lO` 显示这两个文件夹都带 hidden 标记。

所以计划里第 5 项要做的事情，现在的免费版已经都做到了。建议：

- 从 Pro 里拿掉这一项；
- 改成商店介绍里的一句免费卖点：“不在 Windows 磁盘上留下 Mac 的隐藏文件”（上架前在 Windows 上实际看一眼）。

测试文件夹已删除。移到废纸篓的那个测试文件（trash-me.txt，1 KB）还在你的废纸篓里，清倒废纸篓时一起删掉即可；它在“希捷 2T”的 `.Trashes` 里，要盘接上才会显示。
