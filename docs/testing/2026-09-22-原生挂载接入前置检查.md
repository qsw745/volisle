# 原生挂载接入前置检查

## 已核实的系统边界

本机 Xcode SDK 的公开 `FSClient.h` 提供 `mountSingleVolume(resource:bundleID:options:)`。只接收已提供的 FSResource 的调用在 macOS 27 可用性保护下通过类型检查，没有实际执行挂载。

该方法要求客户端具备 `com.apple.developer.fskit.mount`，与扩展的 `com.apple.developer.fskit.fsmodule` 不同。现有 `~/Applications/Volisle Test.app` 的实际代码签名未包含客户端挂载权限。官方说明：[FSClient 原生挂载方法](https://developer.apple.com/documentation/fskit/fsclient/mountsinglevolume(resource:bundleid:options:completionhandler:))。

本机 SDK 的 FSBlockDeviceResource 公共头文件禁止默认初始化；其 Swift 接口未发现按 BSD 名称创建客户端磁盘代理的公开工厂。按 `FSBlockDeviceResource(bsdName:)` 编写的仅编译探针被编译器拒绝。公开头文件说明真实磁盘资源由 fskitd 创建，并在系统处理请求时打开设备。因此目前不能把“方法可编译、签入一个 entitlement”直接视为完整的磁盘挂载接入。此结论限定当前 SDK；不是所有未来版本都不存在公开入口的承诺，也没有使用私有 selector 或伪造 URL 代替块资源。

## 本轮代码

新增 `NativeMountPrerequisites`：

- 检查当前系统是否具备该原生 API。
- 通过 Security 框架读取当前程序实际签名中的挂载 entitlement，仅严格的布尔 true 计为存在；数字 1、字符串等不算。
- 无法读取签名时记录 unknown，不能当作已授权。
- 将当前 SDK 的块资源创建入口缺口单独记录。该结构只供诊断，不授予任何磁盘操作权限，也不表示写入引擎已可用。

诊断报告升级为格式 2，加入白名单前置状态；继续兼容读取缺少该字段的格式 1 报告，不输出签名证书、团队标识、设备身份或路径。只读探针同步报告这些状态。主应用仍使用原只读适配器，没有新增可点击的写入按钮。

## 本轮验证

- 新测试先以缺少实现失败；随后 61 项核心测试全部通过，包括 5 项新的权限类型、系统版本、未知状态、诊断兼容和不误报写入能力检查。
- 客户端本地构建通过。
- 原生挂载方法仅类型检查通过；BSD 资源构造探针按预期失败。
- 只读磁盘探针运行成功；NTFS 仍为 readOnly。新格式化卷没有可持久 UUID，不能据此开启自动挂载偏好。
- 已安装副本的实际挂载 entitlement 检查为 false。没有修改签名配置、Apple 账户、系统权限或已安装应用，没有调用 sudo、挂载或写入。

证据：`.workbench/native-mount-20260922/`。此结果不是原生写入适配器完成或真实系统 API 挂载通过。

## 下一步接入范围

官网版应评估固定功能的授权组件，使正常用户操作经一次安装授权完成。该组件只能处理经主应用身份和当前磁盘身份验证的外置 NTFS 操作，不能接受任意命令、任意路径或格式化/修复请求。首次安装、取消授权、后台服务生命周期和完整卸载都必须有实测结果。

开始实现系统侧组件前，仍需明确：客户端身份验证、设备句柄绑定、只读预检结果传递、非强制卸载、失败只读恢复、超时后设备锁保留、当前 UUID 缺失卷的临时身份策略，以及与扩展持有的实际资源再次核对。系统自动识别扩展的路线也需在一次性镜像中验证，不应直接开启对所有真实 NTFS 卷的自动接管。

这些是后续方案约束，不代表授权组件已经实现或安装。Windows、物理拔插、大文件、长期压力与发行验收仍独立待完成。
