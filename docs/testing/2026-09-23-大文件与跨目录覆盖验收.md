# 大文件与跨目录覆盖验收

本轮实现并验证两个覆盖保存能力：分块内容校验、跨目录源文件替换。覆盖功能仍只编译进绑定 64 MiB 可丢弃镜像的实验构建，未对真实 2 TB 磁盘开放。日常候选仍拒绝同名覆盖保存。未修改 qsw 内任何文件。

## 实现

- `ReplacementFingerprint.read` 使用最多 256 KiB 缓冲区流式计算 SHA-256，支持短读累积、非整块结尾和空文件；拒绝无进展、越界返回、读取错误及有符号偏移溢出。去掉 8 MiB 文件指纹限制。不是对任意容量文件都已验证的声明。
- NTFS 桥接新增 `nk_replace_between`，对源、目标两个目录分别验证规范路径、目录类型、文件身份、类型及备份名称碰撞。旧内容先保存在目标目录，再发布新文件；失败不做破坏性的回滚或清理。原同目录 API 保留为兼容包装。普通编译分支继续明确拒绝覆盖。
- 恢复记录增加可选 `sourceDirectory`；旧记录缺失时仍按同目录解释。清理前核对源目录中的原名称确已不存在，两个文件引用和内容都符合记录。活动事务期间保护源目录及目标目录，防止目录移动破坏核对依据。
- 离线检查点导出改为流式读写，校验成功后才报告恢复。仅操作测试目录中的未挂载镜像；不修复 NTFS、不删除恢复副本、不恢复写入。
- 恢复检查现在区分“当前卷”“明确属于其他卷”“无法确定归属”。当前卷的未完成/损坏记录以及无法确定归属的记录会阻止新的写入激活；有效且明确属于其他卷的记录不阻止当前卷。只读审查不授予清理权限。

## 验证

### 原生状态机与故障镜像

- `.workbench/replacement-recovery-gate.log`：Swift 状态机与存储检查通过；32 个实际镜像进程退出/持久化/清理故障用例通过。包含大型指纹、源目录合法性、旧格式记录、错误卷识别和无法识别记录的阻止策略。
- `.workbench/cross-replacement-invalid-paths.log`：1 次正常跨目录覆盖、12 个逐次写入回调失败注入通过。每次均可独立找到新旧内容，旁边的无关文件不变。非法目录及已占用备份名在写入前拒绝。
- `.workbench/cross-replacement-bridge-regression.log`：原桥接回归通过，包含 8 组检查、14 个写入故障、4 个同步故障、14 个进程退出点；普通构建拒绝覆盖且没有额外写入。
- `.workbench/large-journal-export.log` 与 `cross-large-journal-export.log`：约 16 MiB/20 MiB 两个版本，在同目录/跨目录发布后直接退出进程。只读导出两个版本，与预先独立计算的 SHA-256 一致；源镜像不变、写回调为 0，脏卷再次写入被拒绝。

### 真实 FSKit 挂载

最终镜像：`.workbench/fskit-readonly-ijfr8dqr`。
最终实验签名包：`apps/macos/build/signed-replacement-proof-20260923/top.qisw.volisle.app`。
结果：`replacement-result.json`，11 组检查通过；两次挂载均正常分离，挂载点清理完成。重新挂载和 ntfscat 独立读取一致。分配检查覆盖 24 条记录、2,977 个所属簇，无重叠或位图不一致。

系统日志明确记录我们自己的三个发布分支：

- 同目录：旧 10 字节 / 新 10 字节。
- 跨目录：旧 22 字节 / 新 22 字节。
- 大文件：旧 20,971,532 字节 / 新 9,437,206 字节。

另一个只读进程重新读取恢复记录：已完成 3，未完成 0。打开旧句柄后的读写隔离、关闭后新内容保留也通过，但这些操作由 FSKit/系统共同处理，不把仅有外部结果的测试冒充我们原生发布分支的覆盖证据。早期测试观察到此证据缺口后，增加关闭句柄的覆盖场景及明确日志断言，最终验证通过。

## 发布边界及下一步

这些结果不是 POSIX 崩溃原子性、真实断电或 Windows 检查通过的证明。保持实验构建开关和镜像身份限制，完成后恢复日常候选应用；不把实验包留给用户操作真实硬盘。

日常开放前仍须完成：长时间使用时的已完成记录归档（当前入口总数有 256 项边界）、活动记录写入次数上限处理（当前 512 事件）、应用内异常恢复/导出流程、实际应用的安全保存兼容、私有文件权限以及剩余稳定性验证。最终对象回收 API 当前仍要求 macOS 27。不能仅因本轮镜像测试通过，就宣布覆盖功能已经在日常版可用或正式产品完成。
