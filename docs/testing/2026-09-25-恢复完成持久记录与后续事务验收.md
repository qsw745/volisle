# 恢复完成持久记录与后续事务验收

日期：2026-09-25。

## 结果与边界

已实现原生恢复完成记录，保存于认证的独立可信凭据中。只有恢复、设备刷新、读回及独立检查点核对完成后才发布完成记录。记录持久保存后，旧事务不能再读取用于恢复的活动凭据、继续推进或重复执行回滚；同一卷可申请新事务。

40 项新专项、255 项真实 NTFS 引擎镜像检查、204 项相关专项回归与核心包 179 项测试通过。全部磁盘写入只涉及本轮新建的 64 MiB 普通文件镜像；没有操作 qsw、修改已有故障镜像、挂载真实设备、安装后台、替换应用或发布网站更新。已安装应用版本号仍为构建 4。

这不是正式产品恢复能力验收：生产设备身份及独占访问、生产独立检查点、持续挂载恢复、正常提交的安全结束/退役和正式后台/FSKit 接入仍未完成。正式发布阻断保持。

## 实现

- `BlockJournalAuthority.recover` 持有凭据目录和日志目录的独占锁，通过可信回调完成回滚、设备刷新和独立基线核对，再持久保存完成记录。回调重入、回调失败或日志在回调期间变化，均禁止发布成功。
- 完成记录绑定事务 UUID、卷身份、启动区摘要、尺寸、块大小、精确日志凭据及独立检查点标识。检查点标识是可信恢复策略提供的 64 位十六进制值；不能把日志本身或任意用户输入当作生产可信基线。
- 新增 `recoveryCompletion` 查询历史完成状态和 `unresolvedBindings` 枚举未解决事务。历史完成记录不表示磁盘现在仍等于旧基线，也不允许复用旧引擎挂载。
- `requireNewTransaction` 在建日志前执行准入检查；`save` 再次执行相同检查，避免绕过预检查。存在同一 `volumeIdentity` 的未解决事务时，即使启动区摘要、尺寸变化，也拒绝新事务。事务 UUID 永不复用；其他卷仍可准入。
- 完成记录原子替换中断留下完整临时文件时，恢复发布必须重新认证旧状态、候选状态及日志，并由可信回调核对独占设备与候选检查点。缺少核对回调、核对失败或日志损坏均拒绝；不自动丢弃临时文件。
- 可信状态升级为格式 2。格式 1 仍可导入为未解决状态；旧二进制因不支持格式 2 而拒绝读取，避免把终态误当成待恢复事务。HMAC 域保持原协议值，格式版本在认证载荷内。
- 保留旧日志和完成记录，不清除 NTFS dirty，不自动删除或释放日志额度。当前最多 256 条凭据，满额继续拒绝，不为了新事务丢弃旧事务防重放记录。

`BlockJournalStore.withRecoverySnapshot` 新增完成发布阶段：恢复回调返回后先重新核对日志身份，再执行完成记录发布，发布期间仍持有日志锁。新增故障测试曾复现“回调改动日志，检测失败前完成记录已经保存”的错误顺序；修复后此场景不会留下完成记录。

新专项包含：重启读取完成状态；旧事务读、写、恢复和 UUID 重用拒绝；未解决事务阻止新会话；修改几何信息不能绕过准入；已提交日志不能回滚；回调失败、吞掉重入错误、日志改变；完成记录五个写入阶段抛错；进程退出后的候选发布及发布自身再次退出；缺失设备核对、核对失败、缺失日志；有效认证但非法的终态转移；格式 1 迁移及格式降级拒绝；终态凭据占满时不驱逐旧记录。

真实引擎保留此前 247 项矩阵：4 KiB / 16 KiB 物理块、文件/目录创建、逐写入故障、半块写入、日志与凭据不同步、回滚再次中断，以及原文件内容和整镜像摘要核对。所有失败案例的恢复现在通过原生可信存储发布完成记录。

新增 8 项：分别在完成记录写入、文件持久化、原子替换、目录持久化后强制退出；重新打开后确认历史完成记录且不重复回滚；随后同一镜像进行新的真实文件创建并提交，再请求旧事务恢复，整镜像保持新状态，新建文件仍可由独立 `ntfscat` 读取。

测试工具曾因已有状态目录创建报错，停止于第 248 项；修正工具的重开目录处理后，最终完整 255 项通过。失败报告留存，不计为通过证据。此前首轮专项在新 API 尚未实现时编译失败；另外保存了上述日志变化场景的实际断言失败证据，不能把编译失败等同于行为测试失败。

测试中的检查点是镜像挂载前独立保存的完整 SHA-256；卷身份是被独占打开的普通文件 dev/inode，不能外推为已实现真实 NTFS 卷跨连接身份。强制进程退出不是实际断电实验。历史完成查询在后续事务运行后只返回历史状态，不宣称当前磁盘仍匹配旧摘要。
