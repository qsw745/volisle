# 后台可写挂载生命周期接入

## 当前结论

可写挂载的持久归属、跨客户端查询、显式恢复和重启后的待恢复状态已接入后台服务。用户确认本次临时完全磁盘访问后，签名绑定的 64 MiB 镜像已完成真实 root 后台可写挂载、文件写入与同步、客户端退出后保留、活动事务注销拒绝、恢复系统只读及独立回读验收。测试镜像已正常分离，临时完全磁盘访问已关闭。

126 项核心测试、7 项真实签名 XPC 通信检查、本地构建和严格签名核验通过。后台写入证据来自独立的实际镜像验收，不以 XPC 检查代替。普通应用的真实磁盘写入入口继续关闭，不是产品完成或正式发布。

## 实现范围

- 后台记录新增写入用途、`mountingWrite` 与 `writeMounted` 状态。已可写的卷仍占用后台事务，即使发起客户端退出，也不能接收其他事务或注销服务。
- 卸载之前先持久记录；可写激活失败进入恢复路径，恢复失败保留待恢复状态。服务重启把未结束的写入记录转为待恢复，不自动重新写入。跨启动会话的旧记录继续拒绝执行。
- 界面重开后识别 `writeMounted`，保持操作屏障，提供恢复只读入口。准备阶段尚未产生新记录时，查询返回忙碌，避免被其他客户端误判为空闲。
- 新增版本 2 请求，仅表示精确 64 MiB 的无分区镜像设备。原版本 1 的物理分区校验未放宽。
- 后台仅接受签名资源明确绑定的镜像路径、文件摘要、引导摘要、容量和用户。执行前核对当前 IOMedia 身份、虚拟设备属性、镜像映射和普通文件属性；普通构建不包含该授权资源。
- 挂载目录由 root 管理，每次操作使用独立目录；固定命令在已认证用户的登录环境中调用系统挂载工具。恢复使用持久记录与实际系统状态，不依赖进程内临时对象。

构建与签名工具新增 `--write-service-fixture` 显式选项，必须与 `--write-fixture` 同时使用。资源摘要与签名包清单共同核验。该测试配置是一次性镜像范围，不允许任意路径、任意设备或物理卷写入。

## 实际执行和发现

1. 首次镜像绑定暴露旧接口只接受分区设备，新增独立版本 2 请求并补充拒绝测试。
2. 后台服务的 `argv[0]` 是相对路径，导致无法定位签名资源。已改用 `_NSGetExecutablePath` 定位实际可执行文件并验证固定包结构。
3. 修复后请求到达真实后台，签名范围核验通过；原始设备只读打开被系统权限拒绝，返回“系统尚未允许后台组件读取此磁盘。”请求没有进入卸载或新事务落盘阶段。
4. 镜像已正常分离，完整摘要与签名资源中的初始摘要一致；后台最新记录仍为之前已完成的只读操作。本轮未卸载或写入 2 TB qsw；最终观察为 `/dev/disk8s1`、`/Volumes/qsw`、原生 NTFS 只读挂载。设备名只表示本次观察，不可复用为以后操作的身份依据。
5. 用户随后明确允许本次临时权限，并完成系统身份验证。第一次真实写入成功，脚本却把预期的注销拒绝退出码 1 当作异常；清理流程仍完成后台只读恢复并分离镜像。该次完整结果保留，不标为全项通过。
6. 修正脚本对拒绝退出码的处理，补充错误字段、实际服务连接及活动事务仍在的断言；新建另一份镜像并重新本地构建、签名、安装后，完整验收通过。
