# 写入保护与扩展属性增量验收

日期：2026-09-20。沿用官网免费开源、Mac App Store 收费的产品方向；本轮未改变界面和 Logo，未公开发布。

## 实现结果

1. 写会话先以只读方式检查原有 dirty、休眠与日志状态，再使用不自动修改事务元数据的 forensic 方式打开并再次检查。写入前持久化本会话的 dirty 标记；关闭所有文件与元数据后，重新核对引导区与标记，才清理自己的标记。原有 dirty 始终拒绝写入，不自动修复。
2. 块 I/O 短读、短写、读写失败、同步失败，以及文件写入/截断或扩展属性修改失败，会锁定会话。后续写入不能因底层暂时恢复而继续。`nk_umount` 无论成功失败均消耗句柄，避免重试时使用已释放对象。FSKit 保留关闭失败状态，后续 deactivate 不能把此前失败变成成功。
3. C 桥接和 FSKit 增加扩展属性的列表、读取、新增、替换与删除，使用 NTFS 命名数据流；区分已有、缺失、缓冲区不足、空间不足和 I/O 错误。支持空值与中文名称，单值限制 4 MiB。压缩元数据和 ACL 接口明确不支持。
4. 挂载协调器与卸载/推出操作共用进程内物理设备锁。锁覆盖异步操作，取消请求不会提前释放仍被系统操作占用的设备；所有者令牌防止旧操作释放新锁。此锁不替代 FSKit 实际持有设备时的身份验证，也不约束其他进程。

扩展属性修改及现有 link-then-delete 改名不具备事务原子性；失败后可能保留部分结果。保护措施是报错并阻止继续写入，不能表述成断电后数据必然完整。

| 网站与 GUI | 本轮未改动、未重测 | 上轮验收范围保持不变；不把此次底层构建当作新的 GUI 验收 |

新增镜像覆盖：

- 扩展属性创建/替换约束、短缓冲区、空值、中文名称、大值缩短和删除；独立 ntfscat 进程重新读取命名流校验。
- 只读属性可读，属性写入与删除拒绝，写回调为零且整镜像 SHA-256 不变。
- 会话活动期间保持 dirty，单独 synchronize 不清标记，正常关闭后恢复干净状态。
- 独立写进程在完成同步后直接异常退出；随后检查仍为 dirty，再次写挂载被拒绝，镜像不变。
- 短读/短写后恢复回调仍不能继续写；标记同步失败不返回可写句柄。
- 实际写满 64 MiB 镜像，调用方收到错误，后续写入锁定，预先写入的独立文件内容保持不变。
- 逐个注入正常关闭路径中的同步点故障，均返回失败。若故障发生于数据与干净标记已成功同步后的最终清理，标记可能已干净；不能把所有关闭失败都描述成必然保留 dirty。标记恢复只做尽力处理，不保证故障设备上的物理持久化。
