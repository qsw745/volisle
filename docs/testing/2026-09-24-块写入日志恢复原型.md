# 块写入日志恢复原型验收

目标：对前一轮创建中断导致的 MFT/MFTMirr 不一致，验证有预先持久记录时能否准确恢复。范围严格限定新建、未挂载的 64 MiB 普通镜像文件；没有修改真实卷、当前安装应用、权限或公开更新目录。

## 根因证据

上游 `ntfs_mft_records_write` 先写 MFT 再写 MFTMirr。真实回调追踪显示创建时第 3 次块写入为偏移 16384 的 1024 字节 MFT 主记录，第 4 次为偏移 33550336 的 1024 字节镜像副本。在二者之间退出，或第 4 次失败，会出现已复现的不一致。追踪记录在 `.workbench/block-recovery-20260924/trace.json`。

调换顺序仍然有中断窗口，不能作为一致性修复；仅根据哪一份能读就覆盖另一份也没有足够依据。

## 原型实现

`scripts/fixture_block_journal.py` 实现测试用 before-image 日志：

- 开始时绑定普通文件的设备号、inode、大小、引导区摘要和完整镜像摘要；只接受工作区 `block-journal-*` 下的非链接、单硬链接、当前用户所有的 64 MiB NTFS 镜像。
- 每次镜像写入之前，先记录范围、原字节和预期新字节，并对日志执行 fsync。记录按序号和 SHA-256 链核对；日志写入失败时不调用后续镜像写入。
- 在本轮受限模型中，一笔事务包含从干净镜像打开、一次创建及关闭。只有底层关闭成功、镜像刷新完成且提交记录持久后才认为提交；这不是正式 FSKit 常驻会话的提交模型。
- 未提交时先构造虚拟回滚视图，核对完整原镜像摘要和所有记录，确认当前记录范围的字节都属于已记录状态；日志截断、损坏、身份不符、未记录修改或无法解释的字节一律拒绝，规划结束前不写镜像。
- 原日志保留，因此可以在恢复再次中断后重试。完成后重新核对全镜像摘要并记录 rolled-back；重复恢复不再写镜像。已提交事务只核对最终摘要，不回滚。

恢复未清除 dirty 位来绕过保护，而是将有完整日志的整个受限事务恢复为开始前逐字节相同的干净镜像。没有日志的历史失败镜像没有被修复，仍作为原问题证据保留。

## 验证结果

`scripts/test-block-journal.py` 最终 41 项通过，进程退出码 0：

- 文件和目录各 6 个块写入失败点、6 个写回调后进程退出点，共 24 项。每项恢复后全镜像 SHA-256 与开始前完全相同，上游独立 ntfscat 读取哨兵内容一致，预检为 clean，能够重新正常打开和关闭写入会话。覆盖前一轮 4 个 MFT/MFTMirr 不一致点。
- 已提交新内容保留，重复回滚返回零写入。
- 日志截断、篡改、非法尾事件、不同 inode、日志范围内异常字节、范围外修改、软链接和硬链接拒绝，拒绝前后镜像摘要不变。
- 恢复阶段两个位置的中断、真正恢复进程退出、部分恢复写入，以及相互重叠写入均可重新执行，最后恢复完整原镜像。
- 镜像短写可恢复；日志持久失败会阻止真实桥接的镜像写回调；提交记录写入失败不会被当成已提交。

先运行测试确认缺少实现，再加入原型；初轮 25 项、边界轮 38 项、最终补充后 41 项通过。日志为 `.workbench/block-recovery-20260924/red.log`、`green.log`、`boundaries.log`、`final.log`。最终结构化报告：`.workbench/block-journal-nz22r3p7/result.json`。

## 不能外推的范围

这是 Python 隔离验证工具，未链接进应用或后台服务，不是正式驱动故障已修复。当前文件系统镜像重启和字节注入只覆盖进程中断/指定短写，不证明真实物理断电、设备缓存违反刷新、任意扇区撕裂或全 NTFS 故障矩阵。

SHA-256 链提供损坏检测，不抵抗可重写全部日志的攻击者；当前文件锁也是协作锁。正式接入需要可信后台的安全日志存储、资源互斥、设备绑定与恢复授权。

常驻挂载需要逐操作提交边界，不能回滚用户此前已经成功保存的操作，也不能在提交失败时报告成功。还需验证 FSKit 缓存和磁盘缓存的持久顺序、日志限额/磁盘满、重复挂载及恢复中的设备变化。

本机旁路日志不能让 Windows 在盘屿未恢复前自动重放事务。硬盘中断后直接接到另一台电脑、原 Mac 或日志不可用等情形尚无完整方案；正式发布的互操作与恢复要求仍未满足。不得因为本原型通过而清除 `config/release-readiness.json` 的元数据阻断。
