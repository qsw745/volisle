日期：2026-10-15。状态：2026-10-15 所有者确认，第 0 步已验证（`docs/testing/2026-10-15-商店版Pro第0步验证.md`），开始写代码（分支 `store-pro`）。

第一批做三项：菜单栏、防睡眠和合盖前推出、每块盘单独设置。原计划的第四项“不留 Mac 杂文件”第 0 步发现免费版早已做到（访达不在这种卷上写 `.DS_Store`，没有 `._` 文件，`.Trashes`、`.fseventsd` 由引擎加了隐藏和系统属性），已移出 Pro，改为商店介绍里的免费卖点。用一次性内购“盘屿 Pro”解锁，计划随商店版 1.1 发布。1.0（构建 6，免费）正在审核，不受影响。

## 总原则

1. **购买状态只在应用里判断。** 扩展从不检查是否购买，只读应用写进应用组的设置。没买、退款或读不到设置时，扩展按现在的行为工作（全局“默认只读”，读不到就只读）。
2. **不碰写入、检查点、推出这些路径。** 扩展这次只增加两处：挂载时多读一个设置（每块盘的读写方式）、检查点定时器里多发一个活动通知。两处都不改日志、刷盘和恢复的顺序。
3. **设置改了，下次挂载才生效。** 不重新挂载、不中断正在读写的盘，跟现在“默认只读”的做法一样。
4. **所有会改扩展的改动放进同一个版本。** 每次更新扩展都会中断正在读写的盘，更新次数越少越好。`EXAppExtensionAttributes` 一个键都不改（改了系统会把扩展从列表里拿掉，用户要重新打开开关）。
5. **界面：没买的人看到的和现在一样。** 主窗口只多一个小区块；高级功能都放在设置里新增的“高级”一页；菜单栏默认关闭。

## 2. 菜单栏

**看到什么**：一个磁盘图标。点开后列出每块 NTFS 盘：名字、状态（可读写 / 只读 / 正在写入 / 正在推出），每行一个推出按钮；底部是“推出全部”和“打开盘屿”。

**“正在写入”从哪来**：扩展的检查点定时器（每 250 ms 一次，本来就在跑）检查这块盘有没有还没做检查点的写入，或者 3 秒内是否有过写入。状态变化时（空闲 ↔ 写入），往应用组写 `Activity.<序列号>`，再发一个 Darwin 通知。只在状态变化时发，写入路径本身不加任何东西。

**措辞**：盘挂载着的时候，菜单栏不说“可以拔了”。扩展只知道它收到了什么，内核手里可能还有没交过来的数据。空闲时显示“空闲 · 拔下前先推出”；推出成功后才显示“已推出，可以拔下”，几秒后这一行消失。

**应用常驻**：
- 设置“高级”页加两个开关：“在菜单栏显示盘屿”（默认关）、“登录时打开”（默认关，打开时调 `SMAppService.mainApp.register()`）。审核要求自动启动由用户自己选择，所以两个默认都关。
- 菜单栏打开时，关掉主窗口应用不退出，程序坞图标隐藏（`NSApp.setActivationPolicy(.accessory)`）；再打开主窗口时恢复。
- 代码：`StoreApp.swift` 加 `MenuBarExtra` 场景（`.window` 样式，界面跟主窗口共用 `StoreDisks`）；新文件 `StoreMenuBar.swift`；扩展这边在 `NTFSVolume.swift` 的 `startCheckpointTimer` 里接活动通知，状态判断写成纯函数放进 `StoreMount.swift`，在那里测。

## 3. 防睡眠和合盖前推出

两个开关都放在“高级”页，买了以后默认打开：

- **“正在写入时不让 Mac 自动睡眠”**：任何一块盘处于“正在写入”时，创建 `PreventUserIdleSystemSleep` 断言；所有盘空闲 10 秒后释放。这一项只挡“闲置自动睡眠”，挡不住合盖，界面上写清楚。
- **“合盖或睡眠前推出 NTFS 磁盘”**：收到“即将睡眠”后推迟睡眠，逐块推出盘屿挂载的盘，全部结束或等到 20 秒上限就放行睡眠。
  - 推出失败（文件正在使用）：不强制推出（强制推出可能让卷卡在内核里，直到重启），放行睡眠。醒来后菜单栏和通知中心提示“睡眠前没能推出 X：有文件正在使用”。
  - 醒来后，被推出的盘要重新接上才能用（USB 盘推出后，系统要重插才会重新挂载），菜单栏提示“睡眠前已推出 X，重新接上即可使用”。“醒来自动重新挂载”要看沙盒能不能调 `DADiskMount`，第一批不做。
  - 只处理盘屿挂载的盘；系统只读挂载的、官网版挂载的都不管。
- 两项都要应用开着才起作用，所以和“登录时打开”配合；“高级”页里说明这一点。
- 代码：新文件 `StorePower.swift`（电源断言、睡眠通知、推出顺序），推出复用 `StoreDisks.eject`，另加一个带完成回调、不弹错误条的版本。

## 4. 每块盘单独设置

- **能设什么**：读写方式（跟随默认 / 总是只读 / 总是读写），和“接上后在访达中打开”。
- **在哪设**：主窗口选中盘后，详情里多一个“这块盘”区块（只有买了 Pro 才显示）；设置“高级”页列出记住的盘，可以“忘记”。
- **怎么认盘**：用扩展已经在用的 NTFS 序列号（卷 UUID 里带的那 8 字节）。只有被盘屿扩展挂载过一次的盘才能设置；扩展没打开时只显示说明。
- **扩展怎么用**：应用往应用组写 `DiskPolicy.<序列号>` = `readOnly` / `readWrite`，不设就不写。扩展在 `StoreMountPolicy.readOnlyReason` 里多一个参数：
  - `readOnly` → 新理由 `diskPreference`（应用显示“这块盘设成了总是只读”）；
  - `readWrite` → 盖过全局“默认只读”；
  - 值读不到或认不出 → 按全局设置（全局读不到就只读，跟现在一样）。
  - **安全检查照旧**：写保护、需要检查、休眠、日志没清、恢复没完成，这些照样只读，“总是读写”盖不过它们。在 `scripts/test-store-mount-policy.swift` 里加用例锁住这一点。
- “接上后在访达中打开”由应用来做（看到这块盘挂载就调 `activateFileViewerSelecting`），需要应用开着。

独立审查（2026-10-15）没有严重问题，已改：菜单栏消失且没有窗口时退出（不留看不见的进程）；权益验证失败时保留上次结果，只有确认退款才注销登录项；写入中每 4 秒复查一次状态；设置变化立即作用到防睡眠；登录启动时由主窗口自己关闭；最小化的窗口不算关闭；已在推出的盘等它的结果；同一块物理盘只推一次；超时只标记没完成的盘；菜单栏“推出全部”显示失败；认不出的读写方式只丢这一项。
