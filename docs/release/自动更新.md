## 安装保护

正常“安装并重启”和退出时安装均检查保护门禁。暂停新的磁盘操作 → 核对后台事务 → 正常结束读写并验证恢复 → 停止后台组件 → 核对所有 Volisle 卷均已卸载 → 放行 Sparkle 安装。磁盘忙碌、状态未知或组件停止失败均保留旧版本，不强制卸载、不修复磁盘。若更新中止，尝试恢复原组件；恢复失败继续暂停自动读写并显示原因。下次启动根据本机恢复标记注册组件，保留已有系统授权。

当前门禁单元测试覆盖互斥、热插入拒绝、忙碌拒绝、停止失败、核验失败、恢复失败及重复请求。构建 3 → 4 已完成真实盘屿替换、重启、后台组件恢复和 qsw 自动读写恢复；正常卸载被系统拒绝时会保留旧版。实际安装中断和后台恢复失败仍需实机验收。

## 本地构建与签名

- `python3 scripts/prepare-sparkle.py`：下载并校验固定上游源码，使用本机 Xcode 编译 arm64。SHA-256 固定在脚本中，源码归档随对应源码包交付。
- `scripts/build-macos.sh`：嵌入版本化框架，保留安全的内部链接，读取 `config/updates.json`。
- `scripts/prepare-extension-bundle.py` / `scripts/sign-extension-bundle.py`：内部组件由内到外逐个用同一 Developer ID 签名；应用、引擎、后台组件共享递增构建号。
- Sparkle 更新签名使用本机钥匙串账号 `top.qisw.volisle.updates`。私钥不导出、不上传，不进入代码库。公钥可公开。
- 正式更新包必须完成 Developer ID、公证、Gatekeeper、对应源码核对和升级回归。当前验收候选不进入公开更新目录。
- 更新目录及包使用 Ed25519 签名；先验证更新目录，再下载和验证归档，提取前验证归档。更新检查不上传系统概况或磁盘信息。更新路径关闭访问日志。

## 发布顺序

1. 增加 `config/updates.json` 的 `build`，保留同一 Bundle ID、签名团队和 Ed25519 公钥。
2. 本机编译、签名、公证并完成升级测试；生成对应源码。
3. 全部发布验收通过后，在 `config/release-readiness.json` 中记录 ready、空 blocker 列表及本次构建号/SourceProvenance.json 摘要。该记录是构建后的运维验收记录，不纳入自己的源码摘要以避免自引用。`scripts/prepare-update-release.py` 会在使用签名私钥或生成目录前核对；缺失、未完成、旧构建或其他源码记录均拒绝。随后才生成签名目录、ZIP 和配对源码并检查最终成品。
4. 上传版本化归档和源码后校验摘要；最后原子切换已签名 appcast.xml。禁止手工修改签名后的 XML。
5. 从真实 HTTPS 地址回读目录和归档并验签，再检查旧版本可以发现和安装新版本。

回滚公开目录不等于把已安装用户自动降级。Sparkle 不允许常规降级；发生问题时先撤下有问题的更新项，并发布构建号更高的修复版本。

当前更新目录指向 0.3.1（构建 17）。0.3.0 → 0.3.1 已在 macOS 26.6 虚拟机中经线上目录实测更新成功，见 `../testing/2026-09-27-0.3.0到0.3.1自动更新验收.md`。

## 真实失败路径回归

本地构建隔离测试应用：

```sh
cd scripts/fixtures/update-failure
xcodebuild -scheme UpdateFailureFixture -configuration Release -destination 'platform=macOS,arch=arm64' -derivedDataPath .build/out build
cd ../../..
python3 scripts/test-update-failures.py --output-dir .workbench/update-failures-new-run
```

脚本用临时 Ed25519 密钥、独立偏好域和仅监听 127.0.0.1 的 HTTP 服务，执行真正的 Sparkle 下载/校验。覆盖 503、未签名目录、篡改目录、截断下载、错误归档签名、已签名的无效 ZIP；要求匹配具体错误码、到达预期阶段、原应用逐文件摘要不变。测试不访问生产更新私钥，不改安装中的盘屿，不连接后台组件或读写磁盘。不能用这些故障测试替代真实服务的更新恢复测试。
