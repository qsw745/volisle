# 技术可行性报告

核验日期：2026-09-19。结论：**可以推进原生只读客户端与独立官网；尚不能宣布 NTFS 产品可用。**

## 2. 组件职责

NTFS 引擎负责 NTFS 元数据、目录、文件读写和一致性。FSKit 将文件系统实现接入 macOS，不自带 NTFS 语义。Disk Arbitration 负责磁盘发现、事件及挂载管理协调。SwiftUI 提供界面，不参与块设备操作。应用扩展、授权、驱动冲突和再分发是独立问题。

Apple 官方资料：[FSKit](https://developer.apple.com/documentation/fskit)、[文件系统示例](https://developer.apple.com/documentation/fskit/building-a-passthrough-file-system)、[Disk Arbitration](https://developer.apple.com/documentation/diskarbitration)。FSKit 的用户态应用扩展形式及框架层面的商店分发能力，不代表整个盘屿产品必然获批。

## 3. 三条候选路线

| 维护及来源 | 厂商官方技术产品页面仍可访问；具体交付版本、补丁承诺及支持周期未取得 |

| 复现结果 | 未取得 SDK，未构建、未运行；本机已有第三方组件不计为盘屿验证 |

来源：[Paragon File System Link](https://www.paragon-software.com/us/technologies/file-system-link-business/)、[Tuxera NTFS 技术规格](https://www.tuxera.com/app/uploads/2025/06/Tuxera_NTFS_tech_specs_public_20240725.pdf)、[Tuxera 消费软件授权说明](https://macsupport.tuxera.com/hc/en-gb/articles/360020979659-What-are-the-software-licensing-terms)。本节只是来源归纳，不构成对盘屿再分发资格的法律结论。

### B. NTFS-3G + macFUSE 的 FSKit 后端

- NTFS-3G 选定本次实验版本 **2026.7.7**；上游明确标注为安全更新。源码下载 SHA-256：`d67b769025d32860549d35c2147e45024d172f81c540d750390ce3602c059dab`，本地核对一致。
- 上游 `src/ntfs-3g.c`、`libntfs-3g/volume.c` 头部为 GPL v2 或后续版本条款。具体修改、链接及分发组合必须按组件审查；不能凭进程隔离就宣布免除义务。
- macFUSE 官方当前列出 5.4.0，包级范围 macOS 12+、Apple Silicon / Intel。**这不等于 FSKit 后端支持 12+**。后端文档把 FSKit 起点列为 15.4，首页当前重点介绍 macOS 26 用户态路线；因此须分版本验证，不承诺 15.4 实际可用。
- 默认挂载后端为 VFS；验证时必须显式使用 `backend=fskit` 并核对实际后端。禁止静默回退内核扩展。
- macFUSE LICENSE 第 4 条限制商业软件捆绑二进制，包含商业上下文中的自动下载/安装；需事先取得书面许可。不属于“随便免费商用”。
- 后端文档列出挂载点、通知 API、调用上下文及挂载选项等限制；安全设计不能依赖未提供的 FUSE 调用者上下文。
- Finder 挂载目标在技术路径上成立，但本次 **未安装 / 未加载 macFUSE，也未验证 NTFS-3G 与该后端的组合**。NTFS-3G 实验仅编译库与工具，不编译 FUSE 驱动目标。
- 权限边界：FSKit 后端避免内核扩展安全配置流程，但仍可能需要安装、启用扩展，以及经验证的块设备访问权限。此次没有提升权限。
- 本机 arm64 离线镜像实验通过；Intel、真实 15.4、27.2 挂载及 Windows 交叉验证都没有通过记录。

来源：[NTFS-3G 发布](https://github.com/tuxera/ntfs-3g/releases/tag/2026.7.7)、[源代码](https://github.com/tuxera/ntfs-3g)、[macFUSE 官方主页](https://macfuse.github.io/)、[后端区别](https://github.com/macfuse/macfuse/wiki/FUSE-Backends)、[安装说明](https://github.com/macfuse/macfuse/wiki/Getting-Started)、[完整许可](https://github.com/macfuse/macfuse/blob/release/macfuse/LICENSE.txt)。

### C. NTFS-3G 核心直接适配 FSKit

现有 NTFS 核心可以作为 C 库候选；需要单独实现 FSVolume 到目录/文件语义的映射，以及 FSBlockDeviceResource 的块 I/O 桥接。这不是从零写 NTFS，但接入与数据安全工作仍然很大。

关键验证包括对齐读改写、flush、句柄生命周期、目录 cookie、Unicode 名称、属性及错误映射、取消、并发、休眠、dirty 状态、日志及崩溃行为。GPL 条件仍存在，直接适配不会自动改变引擎许可。

调研发现 [xntfs](https://github.com/HuanchuanTech/xntfs) 和 [ntfskit](https://github.com/whereteam/ntfskit) 等直接适配项目。项目 README 的能力、签名与实测自述不能代替盘屿的源码审计和复现；尤其 xntfs 当前可浏览根目录只有文档和许可证，不能把描述中的工程当作已取得的实现。此次未拷贝任何项目品牌或未核验二进制。

进一步核对 ntfskit 根目录有 `NTFSModule`、`fsbundle` 与构建脚本，属于可继续审计的源代码候选。其 LICENSE 将驱动列为 GPL-2.0，应用 UI 列为专有；README 同时出现 macOS 26 架构描述和 15.4+ 要求，不能直接当作已统一的兼容结论。它还包含日志重放、清除 dirty 与格式化功能，必须先审计并排除不符合盘屿首版策略的自动行为，不能原样接入。性能数字仅为项目作者自述，本报告与官网均不引用为产品能力。下一轮可基于固定提交审计驱动代码，但不复制专有 UI。

初始调研结果（2026-09-19）：**SDK 类型检查通过，当时没有盘屿 FSKit 扩展**，未验证加载、Finder 读写或 Intel。用户态扩展授权与真实 Bundle ID/Team 配置需要在具体工程形成后确定。

## 4. 可复现离线实验

在项目根目录：

```sh
python3 scripts/prepare-ntfs-probe.py
python3 scripts/probe-ntfs-image.py
```

准备脚本下载上游固定版本、验证哈希，在 `.workbench` 构建；不安装到系统。实验脚本不接受设备路径，只创建新的普通文件镜像；完成后自动清理。具体数据见 [原始结果](../testing/ntfs-image-result.json)。

| 必需步骤 | 本次状态 | 证据 / 原因 |
| --- | --- | --- |
| 识别测试卷 | 局部通过 | 新建镜像标签 + NTFS 工具根目录读取；不是系统卷枚举 |
| Finder 挂载打开 | 未验证 | 尚未安装/授权并验证后端；避免干扰现有 Tuxera |
| 创建 / 写入 / 读取 / 哈希 | 通过（仅离线镜像） | ASCII、中文空格 Emoji、100 汉字长名、4 MiB 数据 SHA-256 一致 |
| 独立进程重新打开镜像 | 通过 | 同一镜像再次读取内容相同；不等于卸载重挂 |
| 改名 / 移动 / 删除 | 未验证 | 当前实验没有覆盖，不能由写读结果推断 |
| 卸载重挂后校验 | 未验证 | 没有系统挂载 |
| Windows 读取和 chkdsk | 未验证 | 未提供 Windows 测试环境 |
| 风险卷 / 数据安全 | 未验证 | 没有故障注入或异常卷测试 |

## 5. 官网版本核验

2026-09-19 查询官方 npm registry，固定 Next.js **16.3.5**、React / React DOM **19.3.0**、TypeScript **5.9.3**、Tailwind **4.3.3**、pnpm **10.15.0**。锁文件已生成，禁止随意使用浮动 latest。官方 [2026 年 8 月安全通告](https://nextjs.org/blog/august-2026-security-release) 指定修补线 16.3.3，本次采用更新的 16.3.5，生产依赖及完整依赖审计当时均为 0 已知漏洞。

构建机 Node 25.8.0，满足包的最低要求，但不把本机版本当作生产 LTS 选择；部署构建建议再用当时受维护的 Node LTS 独立验证。本项目静态输出，无 Next.js 服务端长期运行进程、数据库或账号系统。

## 6. 放行结论

- 允许：继续只读客户端、状态/互斥单元测试、官网本地预览与文档。
- 阻塞：产品引擎和授权尚未确定，Finder/Windows 验收缺失，系统兼容矩阵未覆盖。
- 后续：先确定商业 SDK 或接受 GPL 的产品方向；准备同一镜像在 macOS 与 Windows 的交叉实验；取得后端安装、真实开发者命名空间与必要权限后，单独开展阶段 2。
- 不安装驱动、不购买、不签名公证、不发布；这些需要具体产物与对应授权。

2026-09-20 增量：GPL 回调桥接与独立默认只读 FSKit 模块已编译；桥接通过 13 组普通镜像检查。加载、Finder、Windows 仍未验证，详见 `docs/testing/2026-09-20-简洁版与开源引擎进展.md`。
